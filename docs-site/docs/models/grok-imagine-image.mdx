# Grok Imagine 图片

Molii 提供三个图片模型，均支持文生图和图片编辑：

| 模型 ID | 定位 | 输出分辨率 |
| --- | --- | --- |
| `grok-imagine-image` | 标准生成与编辑 | `1k`、`2k` |
| `grok-imagine-image-quality` | 更高质量生成与编辑 | `1k`、`2k` |
| `grok-imagine-image-2.0` | 第二代生成与编辑，支持质量档位 | `1k`、`2k` |

生成端点为 `POST /v1/images/generations`，编辑端点为 `POST /v1/images/edits`。两个接口都返回 OpenAI 风格的 `data` 数组。

## 请求参数

| 参数 | 类型 | 必填 | 默认值 | 可选值或范围 | 说明 |
| --- | --- | --- | --- | --- | --- |
| `model` | string | 是 | 无 | `grok-imagine-image`、`grok-imagine-image-quality`、`grok-imagine-image-2.0` | 公开模型 ID。 |
| `prompt` | string | 是 | 无 | 1–10,000 字符 | 生成或编辑指令。 |
| `image` | string 或 object | 条件必填 | 无 | URL、Data URL 或 `{ "file_id": "file_xxx" }` | 单张编辑输入图。 |
| `images` | array | 条件必填 | 无 | 1–3 张 | 多张编辑输入图；与 `image` 合计最多 3 张。 |
| `aspect_ratio` | string | 否 | `16:9` | 见下方枚举 | 输出图片宽高比。 |
| `resolution` | string | 否 | `1k` | `1k`、`2k` | 输出分辨率档位。 |
| `quality` | string | 否 | `medium` | `low`、`medium` | 仅 `grok-imagine-image-2.0` 支持；决定输出质量档位和计费单价。 |
| `n` | integer | 否 | `1` | `1`–`4` | 输出数量。 |

图片生成不接受 `image` 或 `images`。图片编辑必须提供至少一张输入图，`image` 与 `images` 可以任选其一；若同时提供，两者合计仍不得超过 3 张。

`aspect_ratio` 可选值：`1:1`、`16:9`、`9:16`、`4:3`、`3:4`、`3:2`、`2:3`、`2:1`、`1:2`、`19.5:9`、`9:19.5`、`20:9`、`9:20`、`auto`。

## 输入图片格式

编辑输入可以写成 URL 字符串：

```json
{
  "image": "https://example.com/source.png"
}
```

也可以写成带 `url` 的对象：

```json
{
  "images": [
    { "url": "https://example.com/front.png" },
    { "url": "data:image/png;base64,iVBORw0KGgoAAA..." }
  ]
}
```

还可以先通过 `POST /v1/files` 上传图片，再使用当前用户自己的文件 ID：

```json
{
  "image": { "file_id": "file_a1b2c3d4e5f6g7h8" }
}
```

HTTP(S) URL 必须能被服务端直接读取；临时签名 URL 的有效期需要覆盖整个请求。Data URL 会显著增大 JSON 请求体，只适合较小的图片。不要在日志中记录完整 Data URL 或带签名参数的媒体地址。

## 成功响应

```json
{
  "created": 1786300000,
  "data": [
    { "url": "https://media.example.com/result.png" }
  ]
}
```

`data` 的实际数量可能少于请求的 `n`，最终费用按实际返回数量结算。成功结果由 Molii 保存 24 小时，收到响应后应尽快下载，不要把它当作永久地址。

## 当前目录计费

下表采用 Molii 当前的目录计费口径：数值按“1 美元数值对应 1 元人民币”展示。账户实际结算还会应用当前分组倍率，最终以使用日志中的明细为准。

| 模型 | 输入图片单价 | `1k` 输出单价 | `2k` 输出单价 |
| --- | ---: | ---: | ---: |
| `grok-imagine-image` | ¥0.002 / 张 | ¥0.02 / 张 | ¥0.02 / 张 |
| `grok-imagine-image-quality` | ¥0.01 / 张 | ¥0.05 / 张 | ¥0.07 / 张 |

`grok-imagine-image-2.0` 的图片输入单价为 ¥0.01 / 张，输出按质量与分辨率计费：

| 质量 | `1k` 输出单价 | `2k` 输出单价 |
| --- | ---: | ---: |
| `low` | ¥0.04 / 张 | ¥0.06 / 张 |
| `medium` | ¥0.06 / 张 | ¥0.08 / 张 |

生成公式：`输出单价 × 实际输出数量 × 分组倍率 = 最终费用`。

编辑公式：`(输出单价 × 实际输出数量 + 输入单价 × 输入图片数量) × 分组倍率 = 最终费用`。

例如，使用 `grok-imagine-image-quality` 编辑 2 张输入图并生成 1 张 `2k` 图片，倍率为 1：`(¥0.07 × 1 + ¥0.01 × 2) × 1 = ¥0.09`。

## 错误与重试

- `400 invalid_request`：缺少提示词、数量越界、宽高比或分辨率不支持、编辑输入数量不正确。
- `400 content_policy_violation`：请求被内容安全策略拒绝；调整提示词或素材后再提交。
- `401`：API Key 无效、过期或没有权限。
- `429`：触发限流；读取 `Retry-After` 并退避。
- `5xx`：暂时性服务错误。图片 POST 是否已经产生结果可能不确定，业务端不要无条件自动重试付费请求。

完整命令见 [Grok 图片 curl 示例](../examples/grok-image-curl)。
