# 视频 API

Grok Imagine 视频接口采用异步任务。创建或编辑成功后保存公共任务 ID，轮询任务状态，完成后再下载内容。

| 模型 | 文生视频 | 图生视频 | 视频编辑或延长 | 分辨率 |
| --- | --- | --- | --- | --- |
| `grok-imagine-video` | 支持 | 支持 | 支持 | `480p`、`720p` |
| `grok-imagine-video-1.5` | 不支持 | 必须提供图片或参考图 | 不支持 | `480p`、`720p`、`1080p` |

## `POST /v1/videos`

创建 Grok Imagine 视频生成任务。`grok-imagine-video-1.5` 是独立模型 ID，只支持图生视频，不与其他模型映射。

### 鉴权

需要 `Authorization: Bearer $MOLII_API_KEY`。

### 请求参数

请求体类型为 `application/json`。

| 参数 | 类型 | 必填 | 默认值 | 可选值/范围 | 说明 |
| --- | --- | --- | --- | --- | --- |
| `model` | string | 是 | 无 | 两个 Grok 视频模型 | 模型 ID |
| `prompt` | string | 是 | 无 | 1–10,000 个字符 | 视频生成指令 |
| `image` | string 或 object | 条件必填 | 无 | URL、`{ "url": "..." }` 或 `{ "file_id": "file_xxx" }` | 图生视频输入；1.5 单图模式必填 |
| `images` | array | 否 | 无 | 最多一项 | `image` 的兼容数组形式 |
| `reference_images` | array | 否 | 无 | 1–7 个 URL 或 `file_id` 对象 | 仅 1.5；不能与其他媒体输入混用，最高 `720p` |
| `duration` | integer | 否 | `5` | `1`–`15` 秒 | 请求时长 |
| `aspect_ratio` | string | 否 | `16:9` | `1:1`、`16:9`、`9:16`、`4:3`、`3:4`、`3:2`、`2:3` | 输出比例 |
| `resolution` | string | 否 | `480p` | 取决于模型 | 输出分辨率 |

媒体可使用可直连的 HTTP(S) URL，也可以先通过 `POST /v1/files` 上传，再传属于当前用户且未过期的 `file_id`。

### 请求示例

```bash
curl --fail-with-body --silent --show-error \
  --request POST \
  --url "${MOLII_API_BASE_URL%/}/v1/videos" \
  --header "Authorization: Bearer $MOLII_API_KEY" \
  --header "Content-Type: application/json" \
  --header "Accept: application/json" \
  --data '{
    "model": "grok-imagine-video-1.5",
    "prompt": "雨后街道上的反射光，镜头缓慢向前推进",
    "image": {"url": "https://example.invalid/first-frame.jpg"},
    "duration": 5,
    "aspect_ratio": "16:9",
    "resolution": "720p"
  }'
```

### 成功响应

HTTP `200`：

```json
{
  "id": "task_public_123",
  "task_id": "task_public_123",
  "object": "video",
  "model": "grok-imagine-video-1.5",
  "status": "queued",
  "progress": 0,
  "created_at": 1785744000
}
```

保存 `id`。`task_id` 是兼容字段，与 `id` 相同；新代码应优先读取 `id`。

### 错误与重试

- `400`：参数、模型、比例、分辨率或图片输入无效。
- `401`/`403`：API Key 或模型权限无效。
- `429`/暂时性 `5xx`：创建可能已受理，禁止自动重放付费 POST。
- 连接超时时记录本地请求时间和 Request ID，先检查使用记录再人工决定。

### 计费

文生视频：

```text
输出秒单价 × 实际视频时长 × 分组倍率 = 最终费用
```

图生视频：

```text
(输出秒单价 × 实际视频时长 + 输入图片单价 × 1) × 分组倍率 = 最终费用
```

服务端创建时预扣，任务达到终态后按实际结果结算或退款。目录价以模型广场当前配置为准。

## `POST /v1/videos/generations`

这是 `POST /v1/videos` 的等价生成路径，参数、响应、验证和计费完全一致。客户端任选一个路径并保持一致即可。

### 鉴权

需要 `Authorization: Bearer $MOLII_API_KEY`。

### 请求参数

与 `POST /v1/videos` 相同，支持 `model`、`prompt`、单图或参考图、`duration`、`aspect_ratio` 和 `resolution`。

### 请求示例

```bash
curl --fail-with-body --silent --show-error \
  --request POST \
  --url "${MOLII_API_BASE_URL%/}/v1/videos/generations" \
  --header "Authorization: Bearer $MOLII_API_KEY" \
  --header "Content-Type: application/json" \
  --data '{
    "model": "grok-imagine-video-1.5",
    "prompt": "让画面中的猫向镜头走来",
    "image": {"file_id": "file_a1b2c3d4e5f6g7h8"},
    "duration": 5,
    "resolution": "720p"
  }'
```

### 成功响应

返回与 `POST /v1/videos` 相同的 `queued` 异步视频对象。保存响应中的公共 `id`。

### 错误与重试

错误码和重试规则与 `POST /v1/videos` 相同。该 POST 可能产生费用，不要自动重放。

### 计费

与 `POST /v1/videos` 使用同一价格、预扣和终态结算规则，不会因选择别名路径而额外收费。

## `POST /v1/videos/edits`

使用 `grok-imagine-video` 编辑已有视频。该接口不支持 1.5 模型。

### 鉴权

需要 `Authorization: Bearer $MOLII_API_KEY`。

### 请求参数

| 参数 | 类型 | 必填 | 默认值 | 可选值/范围 | 说明 |
| --- | --- | --- | --- | --- | --- |
| `model` | string | 是 | 无 | 仅 `grok-imagine-video` | 编辑模型 |
| `prompt` | string | 是 | 无 | 1–10,000 个字符 | 编辑指令 |
| `video` | string 或 object | 是 | 无 | URL、`{ "url": "..." }` 或 `{ "file_id": "file_xxx" }` | 输入 MP4 视频 |

不要发送 `duration`、`aspect_ratio` 或 `resolution`。编辑任务的实际时长和实际分辨率从任务完成结果取得；客户端不能指定，也不要根据金额反推。

使用 `file_id` 时，Molii 会复用上传时记录的真实时长和分辨率，不会再次从公网下载探测同一文件。

### 请求示例

```bash
curl --fail-with-body --silent --show-error \
  --request POST \
  --url "${MOLII_API_BASE_URL%/}/v1/videos/edits" \
  --header "Authorization: Bearer $MOLII_API_KEY" \
  --header "Content-Type: application/json" \
  --header "Accept: application/json" \
  --data '{
    "model": "grok-imagine-video",
    "prompt": "保持主体运动，加入轻微胶片颗粒和暖色夕阳",
    "video": {"url": "https://example.invalid/source.mp4"}
  }'
```

### 成功响应

HTTP `200`，响应为异步视频对象：

```json
{
  "id": "task_public_456",
  "task_id": "task_public_456",
  "object": "video",
  "model": "grok-imagine-video",
  "status": "queued",
  "progress": 0,
  "created_at": 1785744000
}
```

### 错误与重试

- `400 invalid_model`：编辑使用了不支持的模型。
- `400 invalid_video`：缺少视频或 URL 无效。
- `400 invalid_request`：发送了编辑接口不接受的生成参数。
- `429`/暂时性 `5xx`：不要自动重放；先检查任务和账单记录。

### 计费

```text
(输出秒单价 × 实际视频时长 + 输入视频秒单价 × 实际计费时长) × 分组倍率 = 最终费用
```

编辑结果缺少可靠实际分辨率时，Molii 不猜价；账单摘要会暂时显示 `unavailable` 并等待核对，预扣不会被错误地当成最终结算。

## `POST /v1/videos/extensions`

使用 `grok-imagine-video` 延长已有 MP4 视频。该接口不支持 1.5 模型。

### 鉴权

需要 `Authorization: Bearer $MOLII_API_KEY`。

### 请求参数

| 参数 | 类型 | 必填 | 默认值 | 可选值/范围 | 说明 |
| --- | --- | --- | --- | --- | --- |
| `model` | string | 是 | 无 | 仅 `grok-imagine-video` | 延长模型 |
| `prompt` | string | 是 | 无 | 1–10,000 个字符 | 后续镜头指令 |
| `video` | string 或 object | 是 | 无 | URL 或 `{ "file_id": "file_xxx" }` | 2–15 秒 MP4 输入 |
| `duration` | integer | 否 | `6` | `2`–`10` 秒 | 需要新增的时长 |

不要发送 `aspect_ratio` 或 `resolution`。输出继承输入档位，最高按 `720p` 处理。

### 请求示例

```bash
curl --fail-with-body --silent --show-error \
  --request POST \
  --url "${MOLII_API_BASE_URL%/}/v1/videos/extensions" \
  --header "Authorization: Bearer $MOLII_API_KEY" \
  --header "Content-Type: application/json" \
  --data '{
    "model": "grok-imagine-video",
    "prompt": "继续向前推进镜头，让夕阳逐渐落下",
    "video": {"file_id": "file_a1b2c3d4e5f6g7h8"},
    "duration": 6
  }'
```

### 成功响应

返回 `queued` 异步视频对象。保存公共任务 `id`，随后通过状态和内容接口轮询、下载。

### 错误与重试

- `400 invalid_model`：使用了 1.5 或其他模型。
- `400 invalid_video_duration`：输入视频不在 2–15 秒范围。
- `400 invalid_duration`：新增时长不在 2–10 秒范围。
- 付费 POST 不得自动重放；结果不确定时先查询任务和使用记录。

### 计费

```text
(输出秒单价 × 请求新增秒数 + 输入视频秒单价 × 输入视频秒数) × 分组倍率 = 最终费用
```

输入视频时长和档位在提交前冻结，完成后按真实输出结果结算。

## `GET /v1/videos/{task_id}`

查询 Grok 或其他兼容视频任务的精简状态视图。

### 鉴权

需要 `Authorization: Bearer $MOLII_API_KEY`，并且任务必须属于当前用户。

### 请求参数

| 参数 | 位置 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- | --- |
| `task_id` | path | string | 是 | 创建响应返回的公共任务 ID |

该接口没有请求体。

### 请求示例

```bash
curl --fail-with-body --silent --show-error \
  --url "${MOLII_API_BASE_URL%/}/v1/videos/task_public_123" \
  --header "Authorization: Bearer $MOLII_API_KEY" \
  --header "Accept: application/json"
```

### 成功响应

处理中：

```json
{
  "id": "task_public_123",
  "task_id": "task_public_123",
  "object": "video",
  "model": "grok-imagine-video-1.5",
  "status": "in_progress",
  "progress": 42,
  "created_at": 1785744000
}
```

完成后 `status` 为 `completed`、`progress` 为 `100`。对于 Grok 任务，`metadata.url` 直接返回经过验证的 xAI 临时结果 URL；该 URL 可能过期，应立即下载并妥善保存。失败时 `status` 为 `failed`，并返回公开 `error.code` 与 `error.message`。

| 状态 | 含义 | 是否继续轮询 |
| --- | --- | --- |
| `queued` | 已提交或排队 | 是 |
| `in_progress` | 处理中 | 是 |
| `completed` | 成功终态 | 否 |
| `failed` | 失败终态 | 否 |
| `unknown` | 暂时无法识别 | 是，但受总截止时间限制 |

### 错误与重试

- `404`：任务不存在或不属于当前用户。
- `429`、暂时性 `5xx` 和传输错误：GET 可以每 2–5 秒轮询并逐步退避。
- 设置单次请求超时和总轮询截止时间；未知状态不能当成成功。

### 计费

查询不产生第二次生成费用。该精简视图不保证包含完整人民币账单；需要计费摘要时，可查询同一公共任务 ID 的兼容任务视图，或在 Molii 生成记录中查看最终明细。

## `GET /v1/videos/{task_id}/content`

为已完成任务提供受保护的结果入口。该入口会先验证当前用户对任务的归属以及任务是否已成功完成，然后按平台采用不同的交付方式：

- Grok 任务返回 HTTP `307 Temporary Redirect`，`Location` 指向经过验证的 xAI 临时结果 URL；Molii 不代理 Grok 视频字节。
- Seedance 和其他兼容平台保持原有代理语义，由 Molii 返回 HTTP `200` 完整字节或 HTTP `206` 分段字节，不会改为 Grok 的 307 行为。

### 鉴权

所有平台向 Molii 内容入口发起的首次请求都需要 `Authorization: Bearer $MOLII_API_KEY`。仅 Grok 会返回跨域 `Location`；访问该地址时必须移除 Molii Authorization，不要使用会把凭据转发到其他主机的 `--location-trusted` 或等价选项。Seedance 和其他平台的视频字节直接由 Molii 代理返回。

### 请求参数

| 参数 | 位置 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- | --- |
| `task_id` | path | string | 是 | 已完成任务的公共 ID |
| `Range` | header | string | 否 | Grok 的初始 307 不消费该范围，应在 xAI 请求中重新发送；Seedance 和其他平台则直接向 Molii 发送该头以获取 206，例如 `bytes=1048576-` |
| `If-Range` | header | string | 否 | Grok 应发给 xAI 目标 URL；Seedance 和其他平台应发给 Molii 内容入口，与对应的 `Range` 配合使用 |

该接口没有请求体。

Grok 的 `Range` 和 `If-Range` 应在拿到 307 后发送给 xAI；Seedance 和其他平台的 `Range` 和 `If-Range` 则直接发送给 Molii。

### 请求示例

下面仅演示 Grok 分支。先只向 Molii 请求重定向响应，再校验 `Location`；第二次请求不携带 Molii Authorization。响应头和未完成的下载都放入仅当前用户可读的临时文件，并在成功、失败或信号中断时清理：

```bash
set -eu
umask 077
HEADER_FILE=
RESULT_FILE=
META_FILE=
cleanup() {
  [ -z "$HEADER_FILE" ] || rm -f -- "$HEADER_FILE"
  [ -z "$RESULT_FILE" ] || rm -f -- "$RESULT_FILE"
  [ -z "$META_FILE" ] || rm -f -- "$META_FILE"
}
trap cleanup EXIT
trap 'exit 129' HUP
trap 'exit 130' INT
trap 'exit 143' TERM
HEADER_FILE=$(mktemp "${TMPDIR:-/tmp}/molii-grok-headers.XXXXXX")
RESULT_FILE=$(mktemp "${TMPDIR:-/tmp}/molii-grok-result.XXXXXX")
META_FILE=$(mktemp "${TMPDIR:-/tmp}/molii-grok-meta.XXXXXX")

curl --silent --show-error \
  --url "${MOLII_API_BASE_URL%/}/v1/videos/task_public_123/content" \
  --header "Authorization: Bearer $MOLII_API_KEY" \
  --dump-header "$HEADER_FILE" \
  --output /dev/null

MOLII_STATUS=$(awk '/^HTTP\// { status=$2 } END { print status }' "$HEADER_FILE")

[ "$MOLII_STATUS" = '307' ] || {
  echo 'Molii content endpoint did not return the expected Grok redirect' >&2
  exit 1
}

XAI_RESULT_URL=$(awk '
  /^[Ll][Oo][Cc][Aa][Tt][Ii][Oo][Nn]:/ {
    sub(/\r$/, "")
    sub(/^[^:]+:[[:space:]]*/, "")
    print
    exit
  }
' "$HEADER_FILE")

case "$XAI_RESULT_URL" in
  https://vidgen.x.ai/*|https://vidgen.x.ai:443/*|\
  https://files-cdn.x.ai/*|https://files-cdn.x.ai:443/*) ;;
  *) echo 'Rejected unexpected Grok video result URL' >&2; exit 1 ;;
esac

curl --fail --silent --show-error \
  --proto '=https' \
  --url "$XAI_RESULT_URL" \
  --header 'Accept: video/*' \
  --output "$RESULT_FILE" \
  --write-out '%{http_code}\n%{content_type}' >"$META_FILE"

XAI_STATUS=$(sed -n '1p' "$META_FILE")
XAI_CONTENT_TYPE=$(sed -n '2p' "$META_FILE")
case "$XAI_STATUS" in 200|206) ;; *) exit 1 ;; esac
case "$XAI_CONTENT_TYPE" in video/*) ;; *) exit 1 ;; esac
mv -- "$RESULT_FILE" result.mp4
RESULT_FILE=
```

不要把 `MOLII_API_KEY` 传给第二条命令，也不要在脚本输出或日志中打印 `XAI_RESULT_URL`。

### 成功响应

- Grok：Molii 内容入口返回 HTTP `307`，并在 `Location` 中给出经过验证的临时 xAI URL；xAI 随后可能返回 HTTP `200` 完整内容或 HTTP `206` 分段内容。
- Seedance 和其他平台：Molii 内容入口自身返回 HTTP `200` 或 `206` 并代理视频字节，不返回 Grok 的 xAI `Location`。
- 两个分支最终内容的 `Content-Type` 都应为 `video/*`，常见为 `video/mp4`，并可能包含 `Content-Length`、`Content-Range`、`Accept-Ranges` 和缓存相关响应头。

下载前应验证 HTTP 状态和 `Content-Type`，不要把 JSON 错误体保存成 `.mp4`。

### 错误与重试

- 任务未完成、失败或内容暂不可用时，不要把响应写入视频文件。
- 短期地址过期后不要假定重新查询会延长有效期；需要时重新生成结果。
- `429`、暂时性 `5xx` 和传输错误可在总截止时间内退避重试 GET。
- 下载 URL 和签名参数属于临时凭据，不要写入分析日志或公开分享。

### 计费

下载本身不再次收取视频生成费用。结果由 xAI 临时托管，不应据此推断 Molii 提供持久存储。
