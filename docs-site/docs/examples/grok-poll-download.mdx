# Grok 任务查询与下载

先设置创建响应中的公开任务 ID：

```bash
export MOLII_API_BASE_URL='http://127.0.0.1:3000'
export MOLII_API_KEY='YOUR_API_KEY'
export TASK_ID='task_REPLACE_WITH_YOUR_TASK_ID'
```

## 查询任务状态

```bash
curl --location --include --request GET \
  "$MOLII_API_BASE_URL/v1/videos/$TASK_ID" \
  --header "Authorization: Bearer $MOLII_API_KEY" \
  --header 'Accept: application/json'
```

当 `status` 为 `queued` 或 `in_progress` 时，每隔几秒重复这个 GET。遇到 `429` 时遵循 `Retry-After`；暂时性 `5xx` 可以退避重试。设置总截止时间，避免无限轮询。

`completed` 表示可以下载；`failed` 表示任务终止，不要为了重试而自动再次发送原付费 POST。

## 查询兼容状态与计费

```bash
curl --location --include --request GET \
  "$MOLII_API_BASE_URL/v1/video/generations/$TASK_ID" \
  --header "Authorization: Bearer $MOLII_API_KEY" \
  --header 'Accept: application/json'
```

该响应的 `data.billing` 会给出 `state`、`final_cost`、`group_ratio` 和模型对应的安全计费明细。仅在 `state` 为 `settled` 时把 `final_cost` 当作最终费用；`refund_pending` 需要继续查询，`unavailable` 不应由客户端自行猜价。

## 安全跟随下载重定向

Grok 的受保护内容入口先返回 HTTP `307`。下面的分段命令把响应头和未完成的下载保存到仅当前用户可读的临时文件；无论成功、失败还是收到中断信号，trap 都会清理临时文件。第一步只向 Molii 发送 API Key：

```bash
set -eu
umask 077
HEADER_FILE=
RESULT_FILE=
META_FILE=
cleanup() {
  [ -z "$HEADER_FILE" ] || rm -f -- "$HEADER_FILE"
  [ -z "$RESULT_FILE" ] || rm -f -- "$RESULT_FILE"
  [ -z "$META_FILE" ] || rm -f -- "$META_FILE"
}
trap cleanup EXIT
trap 'exit 129' HUP
trap 'exit 130' INT
trap 'exit 143' TERM
HEADER_FILE=$(mktemp "${TMPDIR:-/tmp}/molii-grok-headers.XXXXXX")
RESULT_FILE=$(mktemp "${TMPDIR:-/tmp}/molii-grok-result.XXXXXX")
META_FILE=$(mktemp "${TMPDIR:-/tmp}/molii-grok-meta.XXXXXX")

curl --silent --show-error --request GET \
  "$MOLII_API_BASE_URL/v1/videos/$TASK_ID/content" \
  --header "Authorization: Bearer $MOLII_API_KEY" \
  --dump-header "$HEADER_FILE" \
  --output /dev/null

MOLII_STATUS=$(awk '/^HTTP\// { status=$2 } END { print status }' "$HEADER_FILE")

[ "$MOLII_STATUS" = '307' ] || {
  echo 'Molii content endpoint did not return the expected Grok redirect' >&2
  exit 1
}
```

第二步从私有临时响应头读取 `Location`，并在请求前执行精确 allowlist 校验。视频只允许 HTTPS 的 `vidgen.x.ai` 或 `files-cdn.x.ai`，可以省略端口或显式使用 `443`；不能使用 userinfo、子域名、后缀匹配或其他端口。校验通过后的第二次请求不携带 Molii Authorization：

```bash
XAI_RESULT_URL=$(awk '
  /^[Ll][Oo][Cc][Aa][Tt][Ii][Oo][Nn]:/ {
    sub(/\r$/, "")
    sub(/^[^:]+:[[:space:]]*/, "")
    print
    exit
  }
' "$HEADER_FILE")

case "$XAI_RESULT_URL" in
  https://vidgen.x.ai/*|https://vidgen.x.ai:443/*|\
  https://files-cdn.x.ai/*|https://files-cdn.x.ai:443/*) ;;
  *) echo 'Rejected unexpected Grok video result URL' >&2; exit 1 ;;
esac

curl --fail --silent --show-error \
  --proto '=https' \
  --url "$XAI_RESULT_URL" \
  --header 'Accept: video/*' \
  --output "$RESULT_FILE" \
  --write-out '%{http_code}\n%{content_type}' >"$META_FILE"

XAI_STATUS=$(sed -n '1p' "$META_FILE")
XAI_CONTENT_TYPE=$(sed -n '2p' "$META_FILE")
case "$XAI_STATUS" in 200|206) ;; *) exit 1 ;; esac
case "$XAI_CONTENT_TYPE" in video/*) ;; *) exit 1 ;; esac
mv -- "$RESULT_FILE" grok-result.mp4
RESULT_FILE=
file grok-result.mp4
```

最终响应应为 `200` 或 `206` 且 `Content-Type` 为 `video/*`。不要使用 `--location-trusted`，不要把 `MOLII_API_KEY` 加到第二条命令，也不要打印或记录完整 `Location`。xAI 结果 URL 是临时地址，可能过期；任务完成后应及时下载并妥善保存。
