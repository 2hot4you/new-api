# 需求增强说明

1. Grok 图片生成和图片编辑消费记录继续写入通用 `logs` 表，禁止复制日志或新增冗余表。
2. `/usage-logs/drawing` 增加 Image API 与 Midjourney 二级标签，Image API 默认展示两个 Grok 图片模型的通用消费记录。
3. 服务端必须提供数据库层可分页分类筛选，前端不得合并 `/api/log` 与 `/api/mj` 结果。
4. 新 Grok 图片日志必须快照模型、操作、分辨率、比例、请求输出数、实际输出数、输入数、输入/输出单价、小计、分组倍率和最终费用。
5. 详情、桌面列表和移动端不得展示内部 `model_price=1` 与哨兵 Token 1/0。
6. 历史记录不得推测缺失参数；只显示模型、最终扣费与兼容提示。
7. 不修改数据库结构，不引入真实密钥，不改变 Grok/Seedance/Midjourney 以外的计费行为。
8. 遵循测试先行；验证 Go 单测、Go 格式、Web 单测、类型检查、lint、build 与本地页面。
