# Molii Grok 管理凭据渠道化需求

## 已确认目标

- 在添加和编辑 `Molii Grok Imagine API` 渠道时配置系统访问令牌与管理用户 ID。
- 系统访问令牌作为敏感字段保存，不进入普通 `settings` JSON，不通过渠道查询接口回显。
- 编辑时令牌留空表示保留原值；显式清除必须通过独立操作表达。
- 管理用户 ID 必须为正整数，并与系统访问令牌成对生效。
- 查询余额优先使用渠道保存的管理凭据；已有环境变量继续作为旧部署的兼容兜底。
- 获取模型继续使用渠道自身 Key 调用 `/v1/models`，保持已经过联调验证的真实契约。
- 管理根地址仍由 `MOLII_GROK_NEW_API_BASE_URL` 控制，不在渠道表单暴露。
- 不实现或讨论 Molii Grok / Seedance 渠道切换、故障转移或多渠道调度。

## 安全约束

- 令牌字段使用 `json:"-"`，任何 API 响应、错误、日志与审计详情均不得包含明文。
- 只有具备渠道敏感写权限的管理员可以修改或清除管理凭据。
- 数据库存储遵循现有渠道 Key 的保护模型；示例与测试不得包含真实令牌。
- 环境变量兜底必须按“令牌 + 用户 ID”完整凭据对使用，禁止把数据库半套凭据与环境变量半套凭据拼接。

## 兼容规则

- 新增渠道时，渠道表单要求填写完整管理凭据。
- 编辑已有渠道时，空令牌保留原值；没有数据库凭据的旧渠道仍可使用环境变量。
- 若渠道中出现半套或无效凭据，明确提示在渠道表单修复，不静默回退或混用。
