# Volcengine 渠道完整重命名与 Grok 可达性测试

## 重命名范围

- 渠道类型 61 的用户可见名称统一改为 `Molii Volcengine Imagine API`。
- 同步更新计费页标题、素材上传状态、错误消息、生成记录标签、测试成功/失败提示及镜像描述。
- 上游返回内容脱敏后统一替换为新品牌名称，避免用户看到 `StarAI` 或旧名称。
- 更新所有受影响的中英文及其他语言翻译键和值和对应测试。

## 兼容边界

- 保留 `ChannelTypeStarAI = 61`、源码包名、内部函数名和数据库渠道类型不变。
- 保留模型 owner `molii-aigc` 不变，避免改变 `/v1/models` 等已有 API 契约。
- 不迁移用户自定义的渠道实例 `name` 字段。
- 不修改 Seedance 模型 ID、路由、请求格式、计费数值或异步任务行为。

## Grok 可达性测试

- 渠道类型 62 的管理动作从“配置检查”改为“可达性测试”。
- 先校验 Key 与固定 Base URL，再解析 URL 并执行带超时的 TCP 连接。
- 仅检查网络可达性，不进行 TLS 握手、不发送 HTTP 请求、不创建图片或视频任务，不产生上游费用。
- 返回清晰的成功或失败消息，并保持密钥不进入错误信息。

## Grok New API 管理能力

- 查询余额使用系统访问令牌与 `User-id` 请求头调用上游 `/api/user/self`。
- 获取模型使用渠道 Key 调用 New API 管理根地址 `/v1/models`。
- 系统访问令牌、用户 ID 和管理根地址使用环境变量配置；示例文件只提供占位值。
- 余额通过上游 `/api/status` 返回的 `quota_per_unit` 从 quota 换算，不能假设本地与上游额度单位永远一致。
- 所有错误必须脱敏，系统访问令牌和渠道 Key 均不得进入响应或日志。

## 验证

- 新增/更新 Go 与前端测试。
- 运行定向测试、`go test ./...`、`go vet ./...`、前端测试、类型检查、lint 和 build。
- 本地重新构建并重启 LaunchAgent 后，在渠道管理页面验证两个渠道的展示和测试动作。

## 流程例外

- 依用户既有明确要求，不调用 antigravity 或 Claude。
- 依用户本轮明确要求，使用子智能体按后端管理、后端品牌、前端展示与独立审查分工协同。
