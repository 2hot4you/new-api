# Independent frontend implementation analysis

Scope: analysis only. Read requirements/plan and current editor/catalog UI. No application edits, tests, server calls, external writes or child agents. Other owners' work must be preserved. This is a native independent analysis, not an external antigravity/Claude result.

## Task 1: smallest coherent behavior

1. **One shared editor prerequisite, separate from pending.** Keep `isSaving` exclusively actual mutations. In `model-pricing-sheet.tsx`, add a distinct disabled reason/prerequisite presentation used by desktop, mobile and embedded callers. The existing `hasMetadata` draft field can inform this, but unknown/loading and explicitly false must not be conflated. Save label remains “Save model prices” while metadata is missing; only actual pending says “Saving...”. Do not leave embedded reset enabled for the same forbidden write. A safe metadata-management link can target the existing `/models/metadata` route; do not invent a create endpoint, form values, currency or price. Prefer a separate-tab explicit link or existing dirty-navigation confirmation so opening management does not silently lose a price draft.

2. **Reject an entire requested pricing batch before PATCH when any ordinary dirty name has missing/unknown exact metadata.** `buildPricingChanges` currently silently skips `has_metadata=false` and admits absent entries with `empty_version`. Replace those two asymmetrical outcomes with an explicit named precondition error, after filtering the existing four dedicated Seedance names. Determine dirty model names first; untouched builtin/default entries must not block an ordinary change. Preserve the original form and baseline on rejection, and do not separately save ExposeRatioEnabled first. The current caller catches builder errors inside its try block, so this is a small atomic frontend boundary; backend remains final authority. Keep protected-only/mixed Seedance messaging and version/currency behavior intact.

3. **Add means price an already-created exact metadata row.** The full initial snapshot already includes unconfigured exact metadata (`GetModelPricingSnapshot`), so a newly typed pricing name may be eligible even if absent from the visible price table. Check the trimmed typed name against that snapshot before committing/sending. If no eligible entry exists, show the named prerequisite and management/reload action; do not claim it was saved. If supporting metadata created after page load, explicitly fetch the single typed name or reload the snapshot, using its returned version/currency for that new-name eligibility only. Do not silently refresh every edited model's expected_version, because that would weaken conflict detection. A per-keystroke backend request is not required by the approved design. Unknown/query-failed must not be treated as USD eligibility.

4. **Deletion remains a local complete-draft replacement until save.** Add one form-level save/apply action that survives closing/deleting the selected or last row. Do not add immediate DELETE or implicit PATCH to the row menu. Route it through the existing `handleSave` and shared whole-batch preflight. Avoid two identical save buttons when an editor is open. A missing-metadata override deletion must produce the same named rejection instead of silent omission. Keep the local draft on server failure. Plain builtin-only rows have no administrator override to remove: explain/default-label that state rather than suggesting the compiled quote/model is deletable. Removing a real override can legitimately reveal a builtin fallback again.

5. **Reset-all targets eligible persisted overrides only.** Minimal safe selection is non-Seedance entries with `has_metadata===true` and non-empty `configured`; never use display-only `options` maps as the persisted-override inventory. If configured overrides are skipped for missing metadata, state their names truthfully before confirmation/result; alternatively reject the whole requested reset clearly. The plan explicitly permits either; silently reporting a total reset is not acceptable. A builtin-only inventory must be a no-op notice and no PATCH. Retain server reset semantics and confirmation; do not reinterpret reset as deleting the model or disabling its compiled builtin. Embedded single-model reset likewise needs metadata eligibility and meaningful override state.

## Task 2 UI integration boundary and risks

- Existing catalog mutations use `retry:false`, `onError -> getServerErrorMessage -> feedback` in `catalog-sync/index.tsx:193-229`; the existing destructive Alert is enough. A backend typed conflict response with an allowlisted localized message key/params can flow through the existing error helpers without changing global HTTP handling. If structured fields need special rendering, keep the decoder inside Task2-owned catalog-sync files, accept only the exact conflict code and reason allowlist, and support both Axios HTTP errors and existing business-failure causes. Do not regex-match arbitrary backend messages or expose raw compiler/SQL/expression text.
- Configuration-ready status must remain configuration-ready; a prospective price conflict is a separate blocked operation. Do not relabel it as source transport failure or mark the snapshot selectable/executable.
- **Important stale-plan case:** a failed new preview currently leaves an old `plan/currentPlan/finalPlan` in state. For a typed validation conflict, ensure the old preview cannot still present an enabled Review/Apply path as though the new preview succeeded. Clear/invalidate only unsent preview/resolve state as appropriate; never discard a durable/pending operation binding/receipt or turn an uncertain apply into safe retry. Test success-preview -> typed-conflict-preview -> no executable stale action, as well as fresh conflict with no plan.
- Test actionable named Grok/xAI fixed-vs-task conflict and a generic unknown-error fallback. Model/provider identifiers are text, not rendered HTML; no expression, SQL, token or arbitrary raw exception should reach the page. Keep existing auth/proof receipt recovery tests, including consumed proof and committed/pending outcomes, unchanged.
- No Task1 files need to be modified by Task2. Both owners report exact new message keys/params to the exclusive locale owner; all seven locales must be covered. Do not add generic global error behavior, new navigation/search schema, pricing conversions or dependencies as incidental scope.

## Remaining judgment to make explicit

The narrow implementation must choose reset-all's “skip with named notice” versus “reject when configured blockers exist” policy. Whole-batch rejection is simplest for JSON and strongest against misleading partial success. For reset-all, selecting only eligible persisted overrides is explicitly approved if the UI truthfully describes that subset. Neither choice authorizes metadata creation, quote deletion, automatic catalog apply or weakening deterministic Grok rejection.
