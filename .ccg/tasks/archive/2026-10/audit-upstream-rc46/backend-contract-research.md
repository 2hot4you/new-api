## Database migration and rollback implications

The rc.40→46 `model/` diff has 44 changed files, but most changes are query, behavior, localization or tests. The material schema additions found in model tags/startup are:

1. `model/main.go` adds `&UserAccessToken{}` to master-node `AutoMigrate`, plus `EnsureLegacyAccessTokenRetireAt` initialization after auth-version initialization. `model/user_access_token.go` defines `user_access_tokens` with unique token_hash, indexed user_id and expires_at, name/scopes/hint and usage metadata. Existing users.access_token and access_token_created_at columns remain; upstream labels them deprecated. A deployment-wide `LegacyAccessTokenRetireAt` option establishes a 30-day transition. This requires an operator-visible migration of dashboard automation credentials; do not infer that unchanged browser login proves PAT compatibility. No authentication safety claim is made here.
2. `model/usedata.go` adds int64 `quota_data.cache_read_tokens` and `cache_creation_tokens`, both default 0. Aggregation paths and `model/log.go` write/read them. No historical log backfill was identified in this delta: old aggregate rows default to zero, so new cache charts cannot be assumed to reconstruct historical totals.
3. `model/audit_log.go` adds `idx_audit_time_event(created_at,event_id)` while retaining the EventId unique index. This is log-database migration work, including a separately configured PostgreSQL log DB. f9a0634f8 fixes the PostgreSQL test's index-column ordering query; it is not a second schema migration. Index creation can require a production maintenance budget proportional to table size.
4. Channel priority drag uses existing `channels.priority` and `abilities.priority`; no new column. `model/channel_priority.go` updates both under one transaction, row locks on PostgreSQL, revision conflict detection and preview/restore behavior. `model/channel.go` now uses `COALESCE(priority,0)` and deterministic id tie-breaking. A downgrade does not undo changed priorities.

No GORM core or PostgreSQL dialect version bump appears in go.mod between these tags. Production PostgreSQL still opens through `postgresMigrationDialector` with `PreferSimpleProtocol:true` and GORM prepare disabled (`model/main.go`). Preserve this connection policy when reconciling startup conflicts.

Local migration behavior must remain alongside upstream additions: fetched c244's model/main.go includes marketplaceOrderLock, TaskBillingJob, MoliiFile, `MigrateCatalogSync`, marketplace metadata schema, fail-closed options primary-key migration, and `RunCatalogDataMigrations` after authoritative recovery. Non-master startup verifies options key uniqueness. Replacing migrateDB/InitDB wholesale with upstream would remove these contracts. `model/option_primary_key_migration.go` contains local transaction/lock/deduplication changes; merge upstream message changes without discarding them.

Rollback must target a pre-upgrade image built from this customized fork, with coordinated database/options/plugin inventory backup. Extra columns/tables alone may be tolerated by old code; new PATs, new plugin capability declarations, newly selected upstream protocols, and already submitted pending tasks may not be. Do not rely on a binary rollback to undo the retirement option, channel priorities, plugin inventory or newly created tasks. Preserve the old schema fields and catalog revision/ack state; avoid automatic down-migrations. Staging must check fresh PostgreSQL initialization, upgrade from representative c244 data and repeated startup/idempotency, with a PostgreSQL log DB if configured. These are proposed checks, not executed evidence.

## Plugin API remains v1, but host semantics materially change

`docs/plugin-api/v1.md`, `.schema.json`, `.d.ts`, pkg/jsplugin and the task adaptor must be updated as one contract.

- Runtime is now moejs v0.1.0-alpha.7, not Sobek. Hooks receive lazy host-backed plain JSON. Inputs must be treated as read-only and not retained in module globals; host code must not mutate maps after passing them to a hook. Returned values can be the original host object, and JS integral results can be int64 rather than float64. The upstream adaptor's cloning and numeric conversions are correctness changes, not optional refactoring. Porting only the engine risks data races or misread facts.
- Optional hook presence is captured at load: an undefined export later assigned a function stays absent. Existing uploaded custom plugins with dynamic hook exports need a compatibility check. Engine remains synchronous/no arbitrary module imports.
- `json-order@1` changes request object enumeration and outgoing JSON member order. New hosts accept old manifests; older hosts reject unknown capability versions. `duration-auto@1` permits exactly -1 duration before submission but usage quantities remain non-negative. Forwarding -1 must reserve the model maximum and settle measured facts.
- `utils.fetch` is GET/HEAD only, channel-host/allowedHosts restricted, response at most 1 MiB; up to 4 fetches, 15 sec each, total 30 sec per hook. It is available only in specified driver hooks after channel selection, no JS slot during network wait, and no redirects followed. New Hailuo logic depends on this supporting host; installing the plugin first on rc.40 can fail at runtime even though apiVersion remains 1.
- json.clone is available without a declaration; json-clone@1 remains accepted. SSE delta can be selected by exported delta hook without the old capability declaration; the old explicitly declared behavior remains supported. Rolling back the host while retaining a plugin that relies on auto-selection is unsafe.
- rc.46 request-header overrides apply after plugin/adaptor descriptor headers on submit, query, batch query and credentialed content. Client-header passthrough applies only to submission; background polling gets static values and {api_key}. Existing channels with configured overrides can change outgoing behavior, so this needs a staging fixture with overrides and poll requests.
- rc.46 single/batch task query redirects forward credentials only to the channel base host or existing allowedHosts, matching host/port. Untrusted hops strip all but Accept/Accept-Language and cannot regain credentials on a later trusted hop; HTTPS downgrade rejected; 307/308 body replay allowed only on a trusted chain. Existing providers depending on credentialed cross-host redirects need an explicit trusted-host inventory. `allowedHosts` grants actual credential recipients; do not add hosts blindly.
- Hailuo/Vidu/Veo gain New API bindings in rc.45. Existing local channel IDs differ from upstream (next section), so text in upstream docs saying Task Plugin is type 61 cannot be copied into local runtime checks as a literal.
