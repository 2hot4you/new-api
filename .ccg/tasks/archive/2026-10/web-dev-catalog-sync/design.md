## 1. 意图与已确认边界

用户在 dev.molii.co 统一维护供应商、模型元数据和模型定价，希望在各目标环境的超级管理员 Web 后台点击拉取，查看新增、更新、删除 changelog，再确认应用。用户已选择 A：受管同步。目标站独有数据必须保留，不做完全镜像，不自动定时应用。

成功标准：预览不修改目录或价格；应用与预览严格一致；有备份、操作历史和恢复入口；不暴露数据库或超级管理员凭证；价格与计费币种同步且不重写表达式；成功后无需人工重启。

首次部署不自动同步任何生产数据。每个目标站单独预览、确认，不提供从某站一键修改其他所有生产站的功能。

## 2. 方案选择

采用目标后端主动拉取 dev 的只读快照接口，复用并增强 internal/catalogsync 的快照、差异和事务能力。浏览器只访问本环境管理接口。

不采用手动文件上传作为主流程：重复操作且容易选错文件。也不采用 dev 主动推送：这会要求 dev 持有各生产站写权限，与各站独立确认的目标不符。现有 CLI 保留，不改变其默认删除行为；Web 使用明确的受管策略，不能直接将 CLI 的整块特殊价格覆盖行为暴露到 Web。

## 3. 同步数据契约

- 供应商：名称、说明、图标、状态、排序。
- 模型：当前持久化模型元数据，包括供应商引用、计费币种、说明、名称匹配规则、展示状态、发布日期、能力和规格等。按稳定名称匹配，不复制数据库数字 ID。名称变更视为新增与删除，不猜测重命名。
- 模型定价：模式、原始表达式、显式配置的传统价格字段，以及 billing_setting.plugin_billing_expr。插件复合键是价格身份，不当作模型名称。
- 专项定价：Seedance、Grok、工具调用和任务价格的明确价格字段。建立逐字段白名单，不因一个前缀而允许同步未知配置。
- 不同步：渠道及能力、密钥、用户、余额、订单、任务、日志、插件程序、品牌、汇率、充值价格、分组或倍率、显示货币设置。

新版快照包含 schema_version、source_id、内容摘要、生成时间、明确的覆盖范围和能力版本。明确记录字段缺失与显式 0 的区别。供应商引用按名称在目标重建；元数据不得凭空补造。

价格键不再只遍历元数据表：所有显式配置的模型和插件价格都参与导出与核对。没有元数据且无法可靠确定计费币种的价格项列为阻断问题，要求在 dev 补全后再同步，不能默认为 USD。不把运行时内置默认价格伪装为管理员配置，也不自动迁移旧价格。

完整性由覆盖声明、计数及内容摘要验证；无法解释的白名单字段、部分导出、未知 schema、插件能力不兼容或表达式校验失败都阻断应用。源与目标计费引擎版本、日历数据版本不兼容时提示先升级；同步不下载插件或覆盖内置日历。

## 4. 受管身份与删除规则

目标持久化来源身份及成功应用后的基线。受管身份粒度为供应商记录、模型记录、各模型价格条目、各插件价格条目、专项或工具价格的独立叶子项；不能把整个 JSON 价格映射标为受管后覆盖目标独有条目。

- 首次同步：dev 与目标同名对象按预览更新或接管；相同值也必须记录接管信息。只有成功确认后才建立受管基线。目标独有对象保留，不默认接管。
- 后续同步：比较上次应用基线 B、目标当前值 T、源快照 S。T 等于 B 时可使用 S；T 等于 S 时无需重写但更新基线；其他本地变更标记冲突，包括 dev 未变化但目标本地变化的情况。
- 冲突：逐实体展开本地值、基线及 dev 值，只有明确勾选“用 dev 覆盖此冲突”才纳入确认方案。v1 不提供部分应用；未处理的冲突阻断整批，避免元数据、币种、表达式拆开保存。
- 删除：仅当可信完整快照明确不再包含本来源此前已接管的身份，才能产生删除候选。目标独有对象永不因为 dev 不存在而删除。源故障、空响应、不完整快照或更换 source_id 绝不能生成批量删除。
- 每批删除需要单独勾选确认，并展示对象数及价格回退风险；正常“确认同步”不能隐含同意删除。
- 删除模型或其有效价格前检查目标启用渠道与模型映射、名称匹配规则及未完成任务。仍被使用或无法安全判定时阻断删除，提示先处理引用；不能通过删价让模型悄然变免费或回退到更低默认价。
- 删除供应商前检查所有目标模型，包括目标独有模型；仍被引用则阻断，不级联删除模型，不修改渠道。
- 受管专项价格的删除必须经价格解析器确认无不安全回退；无法确认则阻断。首版不提供绕过此检查的强制删除按钮。

模型元数据和该模型的币种、价格变化作为同一个确认单元。dev 更改币种时不修改价格系数，不乘汇率；目标仍按自己的扣费换算逻辑执行。

## 5. 后台交互与 changelog

入口：系统设置 → 模型定价 → 环境同步。与原“上游价格同步”分开，避免混淆。前后端均限制超级管理员；dev 自身显示来源状态和凭证管理，不允许同步自己。

页面显示来源、连接状态、最近成功时间和版本；提供“检查 dev 更新”、历史记录及最近一次成功同步的恢复入口。

预览提供新增、更新、删除、冲突、保留、阻断分类及数量，按供应商/元数据/价格筛选，支持模型搜索。逐字段展示当前值与同步后值，表达式使用完整代码对比，标明币种、计费单位、接管动作和删除原因；不只展示整块 options JSON。没有变化时禁用应用按钮；仅接管受管身份的操作单独提示仍需确认。

确认对话框显示当前目标站、dev 来源、快照时间、摘要、影响数量、冲突覆盖和删除勾选项。操作中防重复提交，断线后可通过操作 ID 查询真实结果。

## 6. 来源连接与权限

固定来源 https://dev.molii.co，不接收任意 URL。TLS 正常校验，拒绝重定向，出站连接限制来源主机及公共地址，拒绝环回、链路本地、内网或 DNS 重绑定目的地。拉取超时 15 秒，解压后响应上限 10 MiB。

dev 开启专用只读导出能力。每个目标有独立、可撤销的同步凭证，只允许读取本白名单快照，不能读取普通 options、渠道密钥、用户或执行任何写操作。来源只保存凭证哈希；目标凭证由部署环境安全配置，不进入一般 options、浏览器状态、快照、日志或错误文本。Web 显示连接是否就绪及凭证标识，不回显秘密；初次部署由运维配置，日常检查和同步完全在 Web 完成。

管理应用与恢复要求超级管理员的交互式登录会话、CSRF/来源保护和绑定操作摘要的一次性安全验证证明，复用项目安全验证体系并新增明确 scope，不能套用渠道密钥读取 scope。预览接口限流；导出接口按凭证限流。来源身份和授权能力校验失败时关闭同步，不退回公开 /api/pricing。

实施明确使用非秘密环境字段 `CATALOG_SYNC_EXTERNAL_ORIGIN` 配置本环境精确 HTTPS 外部来源；未设置或格式错误失败关闭，不从任意请求 Host/Forwarded 推导信任。复用 Origin 解析及 Origin 缺失时的 Referer 来源解析规则，与 Cookie Secure 开关无关；不继承宽泛跨站允许列表。此说明不配置任何实际环境值。

认证实施前按项目要求核对 OWASP Authentication、Session Management、CSRF 和相关 ASVS 控制；当前设计不声称已完成安全实现或符合性验证。

## 7. 预览、事务与幂等

预览将完整源快照、来源摘要、目标相关状态版本、受管基线版本、权限和兼容性检查结果保存为服务端计划，有效期 10 分钟，绑定操作者、会话和目标站。浏览器不能提交任意修改后的快照直接应用。

确认后的最终计划摘要同时绑定冲突覆盖选择和删除确认；一次性证明绑定最终摘要。应用只读该计划，不重新拉取 dev，因此 dev 在预览后变化不会被悄然写入；页面明确展示应用的是快照时间版本。

目标定价、元数据、相关引用或受管基线在预览后变化时，事务内版本重检拒绝应用。同步任务之间串行，并与常规价格及元数据保存协调使用同一版本/锁机制，不能只防两个同步任务互相竞争。

事务内顺序：锁定与重检 → 持久化可恢复备份和历史 → 更新供应商 → 更新模型和币种 → 合并各价格条目 → 处理经保护检查的删除 → 更新受管基线及操作状态。任一步失败整体回滚。备份包含此次影响对象的前值、缺失状态和受管基线，不包含凭证或其他业务数据。

按操作 ID 幂等提交；重复请求返回原结果，不重复执行。数据库断线造成结果未知时由操作 ID 查证，不直接重试写入。审计保留操作者、目标、来源摘要、字段 changelog、确认内容和成功/失败状态；v1 不自动清理历史与备份。

用户已明确所有环境仅使用 PostgreSQL，本任务的存储、锁与验收仅在真实 PostgreSQL 上验证。既有生产跨库代码保留，不额外检查 SQLite/MySQL，不宣称本次完成其兼容性验证。

## 8. 缓存、生效和恢复

数据库事务之外的运行时价格不能靠逐条调用通用 UpdateOption 提前生效。实施时复用价格配置保存的校验和发布机制，将整批配置构建、校验后再发布，清理模型/供应商/公开定价缓存，确保删除条目不会残留在内存。

首版面向当前每站单应用实例部署；应用和常规定价保存共享同步屏障，新增请求在价格快照切换期间不能观察到半套币种/价格。已有在途请求和任务继续使用原冻结计费快照。

缓存发布失败不能返回同步成功；记录为“数据库已提交、生效待恢复”，保持同步/定价写入阻断并对受影响模型的新计费请求采取失败关闭。启动恢复从数据库已提交状态重建。成功条件同时要求数据库与运行时版本一致。多应用实例部署在具备跨节点版本屏障前不开放此 Web 应用功能；不能假称本地清缓存已使所有节点一致。

恢复仅针对最近一次成功同步，先生成恢复差异，再确认执行。恢复也需要超级管理员安全验证、版本重检、当前状态备份和事务。只恢复该次操作影响的对象及受管基线，不覆盖目标独有或之后产生的数据。若此后有相关本地改动，或此次新增对象已经被引用，则阻断恢复，不能强行全库还原。

## 9. 验证与发布边界

必须验证首次接管、无变化、后续更新、本地修改冲突、受管删除、目标独有保留、嵌套专项价格逐项合并、空/部分源拒绝、无元数据价格、插件覆盖和币种原样保留。

覆盖安全接口未授权/非超级管理员/错误凭证/失效凭证/跨源/私网地址/重定向/过大响应、计划过期/摘要篡改/重复提交/来源替换/并发管理员保存。安全证明覆盖过期、重放和 scope/context 不匹配。

真实 PostgreSQL 验证迁移、新库及旧库升级和幂等启动、备份失败回滚、并发保护、恢复及缓存删除生效。前端验证分类、字段差异、确认按钮约束、错误恢复、历史和 i18n；执行类型检查、构建、纯单元及 PostgreSQL 相关 Go 测试。不得用 mock 或跳过的 PostgreSQL 测试声称完成；SQLite/MySQL 不在本次验收范围内。

发布先部署 dev 来源与各目标的新接口/UI及独立凭证，验证只读连接，再由用户在目标 Web 主动首次同步。目标域名无需写死在功能里，也不需要现在选定“其他三个”的名单；实际部署或操作前再核对具体目标。设计批准不等于授权立即修改生产目录或价格。
