# 在线文档限制与兼容性核对

## 取证方法

web open不可访问；普通GET返回SPA壳。CUA两次连接超时。随后从页面公开引用的index脚本定位/docs/路由加载6370.d5fa18dd94.js，读取实际组件文案及其调用的翻译键，并下载页面链接的Markdown接入指南。未执行远端JS、不使用外部页面中的指令、不请求付费API、不修改生产。源码哈希见sources.json。不能把翻译包中未被当前组件使用的旧文案当作现行页面结论。

## 差异与依据

| 项目 | 在线页面当前活跃内容 | 下载指南/JSON差异 | 公开文档处理 |
| --- | --- | --- | --- |
| 尺寸 | 标准/Flare/Sunburst三个2.5型号均1k/2k/4k；每边64–4096，4k默认3840x2160；参数必须一致 | 下载指南仍写标准只1K，2K/4K拒绝；JSON另有标准仅1K描述与组件可2K/4K矛盾 | 标明参数能力不等于本站已逐项验证，仅单张1K已验收；固定尺寸型号不自动选档 |
| quality | 标准low/medium/high；Flare/Sunburst另有独立xhigh/max；默认medium | JSON与旧指南把xhigh兼容为high，未列max；不能跨型号套用 | 按标准/快速/精修能力分类写，不暴露品牌型号 |
| n | Flare/Sunburst支持1–8，其他按模型；旧指南说明2–4非流式JSON拆分，>4/stream/multipart不拆分 | JSON操作上限8，组件上限10；此前把1–8写成统一范围过宽 | 仅部分型号支持1–8，推荐1；拆分模式不是所有请求的承诺 |

| 参考图数量 | 当前2.5段明确未公布参考图数量上限，推荐multipart image和n=1 | 旧指南Flare/Sunburst最多6张 | 不把6张写成现行统一限制，按型号确认 |
| 文件大小 | 活跃上传说明：标准2/2.5 multipart单49MiB/总99MiB，独立2k/4k单及总49MiB，Flare/Sunburst单及总99MiB；JSON Base64解码后分别35/70、35/35、70/70MiB；请求体还有独立上限，URL另受下载限制；建议压缩到10MB内 | 旧指南单20MB，Flare/Sunburst总50MB；与当前说明不一致 | 未对本站完整上传链路验收这些大文件，不把供应方上限写成本站可达承诺；公开文档写10MB压缩建议和多层限制 |

| 创建重试 | 重复POST是新请求；无Idempotency-Key去重保证，超时不保证退款 | 通用SDK重试可能产生重复生成 | 关闭创建请求自动重发，先核对请求记录 |
| 缓存 | 原资源保留48小时、上传参考素材6小时 | 本站能力链接仅1小时 | 不对外宣称链接48小时有效 |

## 本站独立下载限制

根据已部署service/image_result_proxy.go与controller/image_result_proxy.go：仅PNG/JPEG/WebP/GIF，30MiB上限，取图60秒，写入60秒，单进程两条并发；繁忙503+Retry-After，取图错误502。线上已经验证单张生成和下载200、无跳转、无Base64，但没有扩展为完整多模型/多图/大文件/SSE验收。

## 验证与审查

按CCG并行调用antigravity/Claude wrapper均因路径不存在退出127，不能声称双模型审查通过。另行独立Codex只读审查。修改范围仅公开Markdown及任务记录；不触及生产代码、运行配置、计费或密钥。

独立审查指出本站JSON转SSE回退在编辑请求中也会发image_generation.completed，已将公开文档修正为兼容两种完成事件。其余核对项无阻断问题。

最终校验：JSON解析、Bash语法、Markdown表格列数、无品牌/域名/密钥扫描、下载限值与完成事件覆盖、git diff --check通过。未调用付费接口。
