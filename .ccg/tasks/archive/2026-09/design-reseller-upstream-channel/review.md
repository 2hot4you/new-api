## 已验证的关键不变量

- 代理实例只保存/展示本地任务 ID 和允许根级管理员查看的 Molii 公共任务 ID，不存储或返回 StarAI 私有任务 ID、Key、原始响应或签名结果 URL。
- 素材按本地用户绑定校验后才访问上游，代理层之间原样透传 `asset://asset-...`。
- 成功任务只使用可信实际 Token 与本地提交时价格快照结算；事实缺失、畸形或不可表示时进入 `review_required`。
- 视频内容使用提交时选中的渠道 Key 鉴权代理；终端 Authorization 不会转发。
- 原有直连 StarAI 的 COS、计费、时间和历史素材行为保持独立。

## 全分支审查与最终修复

高能力全分支审查发现 8 个 Important 问题及 3 个合并前改进项，已在提交 `12fe5ae79` 中统一修复：

- 支持真实直连 StarAI type 61 公共响应嵌套，并由 type 64 严格提取可信 Token 完成结算。
- 401/403 轮询错误不再达到阈值后误判失败、退款；跨重启保留任务和预留额度。
- Base URL 校验覆盖创建、更新、取模、素材、提交、轮询和内容代理，并拒绝凭据、query、fragment 与可识别自环。
- 有效空授权结果会撤销旧模型；畸形或网络失败仍保留当前配置。
- 后台通过本地鉴权能力 URL 播放 type 64 视频，并正确处理 GET、HEAD、Range、inline 与 attachment。
- 多 Key 渠道的临时素材请求只选择一个启用 Key，不发送 Key 集合。
- 统一写入安全的任务时间、请求事实与本地计费快照，避免非零费用展示零单价公式。
- 编辑态取模不会静默使用旧 Base URL/Key/渠道类型；文档删除语义与安全业务错误均已修正。

唯一一次最终复审确认上述 10 类修复有效，但复现出渠道更新在显式 `type: 0`、`type: null` 或大小写变体 `BASE_URL` 时，校验对象与 GORM 实际保存对象不一致。该阻塞项使用真实 handler 与数据库回归测试先红后绿，并在 `f99080642` 中修复：字段存在性按 JSON 大小写不敏感语义识别，零值类型按数据库实际“保留原类型”的语义选择有效渠道进行校验。
