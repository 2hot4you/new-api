# Requirements

- 评估代理商部署一套 new-api，并以 `aigc.ixiaozu.cn` 作为上游时的渠道架构。
- 代理商只持有 Molii 签发的 API Key 和 Base URL，不接触 StarAI Key。
- 覆盖 Seedance 视频提交、异步查询、临时素材、错误透传、模型限制与计费。
- 首版必须完整支持 `/v1/assets` 素材创建、状态查询与删除，`asset://` 引用，视频任务提交、异步查询、结果预览/下载及失败详情透传。
- 代理商平台保留自己的用户级素材权限隔离；Molii 上游不得向代理商暴露 StarAI Key 或原始私有诊断信息。
- 每个代理商部署实例使用独立 Molii 账户和专属 API Key；不得在多个实例之间共享上游 Key。
- Molii 侧按实例独立执行模型授权、额度、计费、素材归属、审计、限流与吊销。
- 新渠道通过实例专属 Key 从 Molii 上游自动读取该 Key 获得授权的模型列表，不要求代理商手工录入模型 ID。
- 支持手动刷新授权模型，并允许代理商在本地禁用其中部分模型；上游已撤销的模型不得继续被标记为可用。
- 模型同步只返回授权模型与协议能力，不向代理商泄露 Molii 批发价、渠道成本或倍率。
- Molii 按代理商实例专属 Key 结算；代理商实例使用自己的价格、用户分组与余额系统向终端客户独立结算。
- 代理商实例不重复保存生成视频；通过自身 `/v1/videos/{task_id}/content` 地址，以实例专属 Key 鉴权读取 Molii 上游内容并流式转发。
- 内容代理必须支持预览、下载、HEAD、Range 请求与必要响应头，同时不得向终端用户暴露 Molii Key、StarAI 地址或真实上游任务 ID。
- 内容读取不得依赖一次性或短时上游签名；代理商实例应使用稳定的 Molii 鉴权内容接口。
- 分销协议不限制代理层数，不增加专用跳数头或多层代理限制；行为与其他 new-api 渠道类型保持一致。
- 仅保留常规安全校验，包括拒绝将渠道 Base URL 直接配置为当前实例自身，防止明显的直接循环。
- 新渠道后台名称为 `ByteDance Seedance`。
- 首版只覆盖 Seedance 视频与临时素材完整链路，不同时接入文本、Claude、Gemini、图片生成或 Grok 等协议。
- 内部结构应允许未来按协议扩展，但首版不得扩大实现范围。
- 比较复用现有 Molii Volcengine Imagine API 类型、新增渠道模式、新增独立渠道类型的成本与风险。
- 本阶段只输出可审阅设计，不实施代码。
