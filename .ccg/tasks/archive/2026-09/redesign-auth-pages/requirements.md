# 初始需求

重新构建 `/sign-in`、`/sign-up` 与 `/forgot-password`，解决当前页面过度留白、层级单薄、品牌感不足的问题。

# 已知约束

- 保留现有认证能力和接口契约，包括密码加密、Turnstile、OAuth、微信、Passkey、2FA、注册验证及法律条款。
- 三个页面共享一致的认证外壳和响应式规则。
- 仅调整认证页面视觉与交互，不改变鉴权安全流程。
- 视觉方案须由用户确认后再实施。

# 已确认设计

- 采用 A「产品叙事分栏」作为认证页主体结构。
- 顶部导航直接复用全局 `PublicHeader`，字体、字重、间距、Logo、语言入口及导航行为均跟随全局配置。
- 页面底部直接复用全局 `Footer`，不在认证模块内维护第二套页脚样式或文案。
- 桌面端在全局 Header 与 Footer 之间显示左右分栏；移动端收拢为品牌摘要 + 单列表单，避免长注册表单横向拥挤。
