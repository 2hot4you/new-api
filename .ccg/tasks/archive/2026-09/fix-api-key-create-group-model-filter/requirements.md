# API 密钥创建分组与模型联动

## 需求

- 创建 API 密钥时不再自动兜底选择 `default` 或列表中的第一个分组。
- 创建表单的名称、分组标签显示必填星号，既有表单校验保持生效。
- 未选择分组时，模型限制不展示全量模型，并提示先选择分组。
- 选择一个分组时，只展示后端实际返回的该分组可用模型。
- 选择多个分组时，展示各分组可用模型的去重并集。
- 分组包含多个 Provider 时，不按 Provider 裁剪，完整展示该分组的所有模型。
- 用户主动更换分组后，移除已不属于新分组范围的模型限制，避免提交隐藏的无效限制。
- 编辑既有密钥初次载入时保留原有分组与模型限制，不因异步数据加载而静默清理。

## 验收

- 创建抽屉打开后，未配置显式全局自动分组默认值时分组为空。
- 名称和分组标签可见 `*`。
- 分组模型查询使用 `/api/user/models?group=<group>` 的实际能力数据。
- 无分组、单分组、多分组、跨 Provider 分组和编辑态都有自动化测试覆盖。

## 兼容约束

- 若管理员明确启用了全局自动分组默认值，保留该显式配置，不把它视为“第一个分组兜底”。
- 不修改后端接口契约和现有 API 密钥持久化格式。
- Provider 分类和图标仅用于界面分组，不参与路由决策。
- 跨分组请求会在本地跳过不包含目标模型的分组，不向这些上游发送请求；渠道亲和性启用时可能优先复用已成功渠道。
