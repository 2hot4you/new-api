## Required test-design details

### 1. Restore the dedicated deadline singleton, not only OptionMap

`EnsureLegacyAccessTokenRetireAt` mutates `legacyAccessTokenRetireAt` atomic (`model/user_access_token.go:305–318`). `preserveCatalogCandidate` restores OptionMap and pricing (`model/catalog_sync_candidate_test.go:49–63`), while `preserveOrdinaryCatalogRuntime` restores runtime/projections and FX/SystemName (`model/catalog_sync_runtime_test.go:75–108`); neither restores that deadline atomic. Save its pretest value and register restoration **before invoking the initializer**, separately per table case. Preserve current request-policy snapshot/typed RetryTimes if a positive control changes it; OptionMap restoration alone does not restore every typed setter's effect. No `t.Parallel`: these tests own process-global DB/runtime/registry/maps/policy/atomic state.

Each none/deadline/theme/both case needs a fresh fixture. Calling the real deadline initializer twice with different deterministic times can additionally prove first-start-wins and unchanged DB value; never use administrator UpdateOption on the read-only deadline. Theme initializer should use its real normalize function; no need to invent a disabled frontend or alter production migration behavior. Stabilize through a real normal loader once, then establish baseline. Assert literal selected row values and dedicated deadline remain fixed across three no-op calls, and ignored keys remain absent from OptionMap. Never seed those keys into OptionMap to make preflight pass.

### 2. The three-engine test cannot reuse the PG-only reload helper blindly

`catalogReloadTestDB` (`model/catalog_sync_reload_test.go:25–45`) requires TEST_POSTGRES_DSN and always uses postgres. For the matrix, use the existing engine-aware `catalogFenceTestDB(t, engine)` plus real `initializeOrdinaryCatalogTest` and the necessary policy/typed cleanup; do not rename a PG fixture as sqlite/mysql coverage. `catalogSyncTestDB` (`model/catalog_sync_test.go:2574ff`) makes disposable per-test databases from loopback test DSNs and a temporary SQLite file; `catalogFenceTestDB` adds real schema/anchors and PG prerequisite. Missing engine fixtures may skip outside guarded gate, so root's local three-engine verification must explicitly confirm every engine and all four cases actually passed, zero skip—not just exit0.

Register write counters only **after** migration/initializer/first stabilization have completed. Existing startup inserts and first legitimate normalization are allowed setup; the measured no-op period must have zero Option/Create/Update/Delete and no catalog mutations. Snapshot the complete CatalogSyncState before/after, plus the relevant stored options and any metadata claimed unchanged. Keep installed pricing money/fingerprint/rows meaningful; do not fake ready or omit schema. Direct optionsOnly tests alone do not prove the outer recovery took no W; that is why the reader integration is necessary.

### 3. Do not accidentally test a loader-induced lock/deadlock

Use the existing loader function seam, not a new production hook. The wrapper must invoke the real `loadOptionsFromDatabaseGuarded` and propagate its real result; a fake nil return or bypassed preflight would invalidate the regression.

The real loader owns OptionMap/request-policy/passkey locks during DB reads (`model/option.go:268–280`). Calling a pricing callback that consults those settings while paused **inside** that lock-held loader can deadlock or create unrelated contention. Rendezvous immediately before invoking the real loader or after it returns and releases those locks. Do not leave the wrapper paused while the coordinator waits for full recovery to complete. Prefer buffered result signals and releases with sync.Once; every pause must also unblock on context cancellation.

Hold a real preexisting catalog R throughout the desired no-op recovery. Coordinate actual optionsOnly entry/result and allow it to proceed. A genuine no-W implementation can complete while this R is retained. Old code returns the real need-writer sentinel, then reserves observable `catalogWriterIntent` and waits for W behind that R; a new `WithCatalogPricingRead` is deterministically barred. Assert completion while R is still held, no writer invocation/intent and a successful new pricing read, not merely success after releasing R. Do not depend solely on “saw intent zero at one instant”: a brief intent could be missed; record any wrapper call with optionsOnly=false or use the retained R to make every erroneous escalation remain observable.

Use a generous outer watchdog only to bound broken tests; short350ms timing budgets and sleeps are not the intended schedule proof. For old-source RED, distinguish exact real sentinel/actual writer-intent rejection from fixture failure, missing schema/DSN, compile failure or timeout before the loader rendezvous. Cleanup must cancel, release all owned pause channels and R, then join recovery **before** removing callbacks or restoring DB/globals. Avoid `require`/Fatal in worker goroutines; return structured error/state to main. Make cleanup robust even when a main assertion aborts early. Verify writer-intent counter and locks return to baseline, not just that the goroutine eventually returns.

### 4. Positive controls must prove narrowness, not merely the ignored-key happy path

Changed **and** missing effective keys are distinct obligations in requirements. Seed a real RetryTimes/policy option with a stable old published value, modify the fixture DB to a valid different value, and assert optionsOnly still returns the sentinel; actual recovery must invoke the writer loader and publish the new effective value. Separately remove only that effective key from OptionMap while keeping its unchanged valid DB row, then require the same escalation/publication. Restore typed policy state afterwards. Do not delete a business DB row to simulate the map-missing condition.

A near-match unknown key such as `theme.frontend.extra` can cheaply assert the predicate is exact, not prefix-based, if added without widening the test's responsibilities. Existing normalization/price/FX/pending/writer-fairness contracts must continue to run unchanged. A genuine settings/price change is allowed to request W: do not demand universal no-W loading or weaken reader admission to satisfy the new test. Genuine normalization work must still execute under W.
