# ByteDance Seedance 代理渠道配置指南

适用版本：包含 `ByteDance Seedance` 原生渠道（类型 64）的 new-api。本文面向独立部署的代理商运维人员；客户请求参数仍见 [Seedance API 接口文档](Molii%20Seedance%20API%20接口文档.md)。

## 1. 选择正确的渠道

| 部署角色 | 渠道类型 | 连接对象与凭据 | 视频结果 |
| --- | --- | --- | --- |
| Molii 直连供应商 | `Molii Volcengine Imagine API` | StarAI 地址与 StarAI Key，由 Molii 持有 | 沿用直连任务的 COS 持久化 |
| 代理商独立实例 | `ByteDance Seedance` | Molii Base URL 与该实例专属 Molii Key | 鉴权代理 Molii 内容接口，不再次保存视频 |

不要把 Molii Key 填入直连渠道，也不要把火山方舟 Ark 地址、StarAI 地址或本实例地址填入代理渠道。已有直连渠道、历史任务、素材及价格不需要迁移或改类型。

首版覆盖 Seedance 视频、临时素材与内容读取；不包含聊天、Claude、Gemini、图片生成或 Grok，也不是通用 new-api 全协议代理。

## 2. 准备与配置

生产使用 PostgreSQL 保存任务与持久化结算作业、Redis 保存临时素材授权绑定。确保数据库、Redis、后台任务轮询及账单调度可用；不能以 SQLite 测试替代生产存储验收。

由 Molii 为每个部署实例分配独立账户并签发专属 Key。不同实例不要共用账户或 Key。终端用户只持有代理商本地签发的 Key，Molii 不需要终端用户的用户名或密码。

在后台新建渠道：

```text
渠道类型：ByteDance Seedance
Base URL：https://aigc.ixiaozu.cn
API Key：由 Molii 为该部署实例单独签发
模型：通过“测试连接并获取模型”自动同步
价格：在代理商实例本地配置，不从 Molii 同步
```

同时设置本地分组、优先级、权重及启用状态。Base URL 必须是绝对 HTTP(S) 地址，生产使用 HTTPS；填写 Molii 接入根地址，不附加 `/v1/video/generations`、查询参数或 URL 用户名密码。系统拒绝能直接识别的自身地址；运维仍应检查反向代理与域名别名，避免间接路由循环。

创建或从其他类型切换到此渠道时必须明确提供新的 Key。编辑同类型渠道时留空表示保留现有 Key，不表示清空。

### 连接测试和模型授权

“测试连接并获取模型”只调用带实例凭据的 `GET /v1/models`，不会创建收费视频。只有同时满足以下条件的模型可以启用：

- 该 Key 的 `/v1/models` 响应中可见；
- 名称是受支持的 `doubao-seedance-*`；
- 本地适配器已有明确能力定义。

目前支持标准版、Fast、Mini 与 2.5 的既有模型 ID；上游新增名称不会绕过本地能力检查。使用模型区的刷新/上游检测、待处理变更及自动同步功能审核授权变化；撤权模型应从可用列表移除。同步失败保留旧模型列表，保留不代表上游授权仍然有效。检查上次检测时间与失败状态，并核对本地启用的子集。

模型同步不读取或导入上游价格、币种、倍率、批发成本或渠道 ID。上线前必须在代理实例配置本地价格及分组倍率；不要认为连接测试成功就已经能计费。

## 3. 临时素材

客户使用代理实例的 `/v1/assets`，代理再访问 Molii 同名接口。返回的 `asset-...` ID 逐层保留不变，但每层都保存自己用户的授权绑定；知道 ID 不等于有权使用。图片、视频和音频在生成请求中使用 `asset://asset-...`。

推荐流程：创建素材 → GET 刷新至 `ACTIVE` 或 `SUCCESS` → 提交引用该素材的视频任务。`PROCESSING` 时等待，`FAILED` 时修正源文件，`EXPIRED` 时重新创建。绑定有效期不超过 Molii 返回的 `expires_at`，通常最多 168 小时；刷新不会无限续期。

- 公网 URL：不要求代理商配置 COS。文件须可直接读取，不依赖额外 Cookie、API Key 或自定义头；签名有效期应覆盖处理所需时间。
- 控制台本地文件上传：必须配置代理商自己的 COS 存储桶、地域、可读域名及凭据。先上传到本地 COS，再提交可读取 URL。未配置 COS 时仍可用公网 URL；Molii 不代传本地文件。
- 查询、删除、生成：先检查本地用户所有权，再验证上游归属、状态及有效期。同一用户的不同有效 Key 可以复用其素材，其他用户及其他上游账户不可以。
- DELETE：只删除当前实例的绑定、可见性和对应本地 COS 对象（如有）；不向上游发送级联 DELETE，上游按自身生命周期过期。不会取消已经创建的视频任务。

新素材优先选取启用的 ByteDance Seedance 渠道，既有直连绑定保持原提供方。首版不承诺同一分组同时混用直连和代理素材账户；不要通过停用渠道来尝试跨提供方迁移素材。

## 4. 视频任务与内容读取

任务 ID 分为三层：

```text
终端用户保存：代理商公开 task_id
代理商私有映射：Molii 公开 task_id
仅 Molii 内部直连诊断：StarAI 原始任务 ID
```

代理商的提交接口为客户生成本地 `task_...`，后台使用 Molii 公共任务 ID 轮询。普通客户响应不包含 Molii 上游任务 ID、StarAI 原始 ID、Key 或原始上游 JSON。代理商根级任务诊断可查看 Molii 公共任务 ID，但不能看到 StarAI ID；不要向普通客户发送根级诊断截图。

新客户端可使用 `/v1/videos`，兼容的 `/v1/video/generations` 继续可用。代理渠道内部向 Molii 使用后者。只保存当前接入实例返回的公共 ID，用它查询和下载，不自行构造 ID。

客户下载请求示例（所有 Key 都是环境变量中的占位配置）：

```bash
export RESELLER_BASE_URL="https://reseller.example"
export RESELLER_API_KEY="replace-with-local-user-key"
TASK_ID="task_replace_with_created_id"
curl --fail-with-body --silent --show-error --max-redirs 0 \
  --url "${RESELLER_BASE_URL%/}/v1/videos/${TASK_ID}/content?download=1" \
  --header "Authorization: Bearer $RESELLER_API_KEY" \
  --header "Range: bytes=0-1023" \
  --output video-part.mp4
```

代理内部使用实例专属 Key 请求 `{Molii Base URL}/v1/videos/{Molii task_id}/content`，不会把客户 Key 转发上游。支持 GET、HEAD、Range、If-Range、206、Content-Type、Content-Length 和 Content-Range；下载附件名由本地生成，不透传上游诊断 Header。不要让携带 Key 的客户端自动跟随重定向。

内容读取不依赖轮询中返回的短期结果 URL，不把 Molii/StarAI/COS 私有地址或签名暴露给客户。结果暂不可读时返回安全的代理错误（例如 502/503），不会把成功任务改成失败、重新生成或重复结算；恢复后重试原内容 GET。

## 5. 两层独立计费与人工复核

Molii 按批发配置向实例账户结算；代理实例按自己的价格快照和分组倍率向终端用户结算。这是两本独立账，不应复制 Molii 金额。

提交时预扣，成功后使用可信的正整数 `total_tokens`（缺省时回退 `completion_tokens`）和提交时本地价格快照差额结算，明确失败则退款。持久化账单作业在服务重启、重试或重复轮询后仍应只结算一次。

成功但缺少可靠用量、用量非法/溢出或价格快照不足时，账单进入 `review_required`。预扣继续保留等待核查，既不是“零费用”，也不能当作已经最终结算。检查公开任务 ID、请求 ID、用量字段、提交时本地价格和账单状态；联系 Molii 核对，不要通过重新创建视频补账。内容下载成功不代表账单复核完成。

## 6. Key 轮换与历史多 Key 注意事项

首版推荐每实例一个上游账户、一个有效渠道 Key。同账户轮换后，新 Key 可以验证该账户原素材；换成另一个 Molii 账户不会转移原素材/任务所有权，会出现未找到、无权或安全验证失败。

轮换前确认新旧 Key 属于同一账户及相同模型授权，先验证 `/v1/models`，更新后用已有素材、未完成任务与成功任务内容逐项检查。不要把多个账户 Key 拼接填入单 Key 配置。

新建代理视频任务会私有保存提交时选定的 Key，轮询和内容代理优先使用该快照；修改渠道 Key 不会自动迁移已提交任务的凭据。素材请求使用当前渠道 Key。没有凭据快照的历史单 Key 任务可回退到当前渠道 Key，但历史多 Key 任务无法确定原 Key 时，内容接口会安全返回 503，而不是把整组 Key 发给上游。因此不能保证一次渠道换 Key 就使所有历史任务无缝切换。撤销旧 Key 前先完成或核查存量任务，必要时联系运维按现有凭据管理流程处理；不要手工复制私有 Key 到日志或客户工单。

## 7. 排障与上线检查

| 现象 | 检查与处理 |
| --- | --- |
| 连接测试失败/没有模型 | 核对渠道类型、Molii 根地址、实例 Key、网络和模型授权；不要靠创建收费任务测试连接 |
| 模型同步失败 | 修复鉴权或网络后刷新，核对保留列表与上游实际授权，不自动清空本地配置 |
| `model_price_error` | 补齐本地模型价格、分组倍率；上游模型同步不会设置价格 |
| 本地上传不可用 | 检查代理自身 COS；也可改用可读公网 URL |
| 素材未找到/验证失败 | 检查本地所有者、创建账户、绑定渠道、Key 是否换账户、`expires_at` 和上游状态；不要尝试其他用户的 ID |
| 轮询超时/429/502/503/504 | 暂时错误保留原任务状态并退避重试；不要将通信失败等同于明确生成失败 |
| `review_required` | 核对实际用量和价格快照，保留预扣等待复核，不猜费用、不重建任务 |
| 成功但播放失败 | 用同一本地 task ID 重试鉴权内容 GET，检查上游可用性及内容代理限制；不自动退款或重新提交 |
| 重启后任务不推进 | 检查 PostgreSQL 持久化任务/账单作业、调度器、Redis 与上游连通性 |

上线至少验证：模型授权同步、本地价格、三种素材的用户隔离与过期、带素材提交、成功结算/失败退款、重启幂等、鉴权 HEAD/Range 下载、Key 轮换和现有直连任务回归。工单仅提供请求 ID、本地公共任务 ID、时间、模型、安全错误码及脱敏参数；上游 Key、签名 URL 和 StarAI 私有诊断不进入客户响应或工单。
