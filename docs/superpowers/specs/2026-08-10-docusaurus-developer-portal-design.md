# Molii Docusaurus 开发者门户设计

## 背景

当前文档首页只包含欢迎语和目录，`/quick-start`、`/platform`、`/api-basics`、`/models`、`/examples` 与 `/help` 等栏目入口页也只有一句简介。顶部导航同时平铺八个入口，用户必须先猜测栏目边界，再进入子页面寻找内容。现有具体指南和 API 参考已经积累了较完整的信息，但入口层没有形成专业的阅读路径。

本次改版把文档从“文章目录”升级为“开发者门户”：首页负责建立产品认知和接入路径，栏目入口页负责解释如何选择内容，具体指南继续承担完整操作和参数说明。

## 目标

- 首页呈现专业、完整且可扫描的开发者门户，桌面内容高度至少覆盖两个 `1440×900` 视口。
- 六个顶部栏目都有内容丰富的入口页，不再出现单段简介或大面积空白。
- 新用户能沿着明确路径完成第一次调用，已有系统的开发者能快速进入 API 参考。
- 保留现有公开 URL、具体指南和 API 端点，不因导航调整破坏已有链接。
- 继续使用 Docusaurus 3.10.2、现有 Serif 字体和桌面 `12px`／移动端 `14px` 根字号。
- 不引入未经实现的模型、SDK、API、参数或计费信息。

## 设计方向

采用已确认的“开发者门户型”首页，而不是 API 手册型或产品知识库型首页。

首页使用温暖的中性色、深色代码面板和克制的强调色建立专业层级。视觉重点依次为产品能力、开始行动、真实代码、接入路径、模型能力、异步任务流程和生产资源。首页使用独立样式；具体文档内页继续使用标准 Docusaurus Docs 布局，避免把营销式视觉扩散到参数表和长篇指南。

## 顶部导航与信息架构

顶部导航由八个平铺入口收敛为六个栏目：

1. `开始使用` → `/quick-start`
   - 接入准备
   - 创建 API Key
   - 第一张图片
   - 视频异步工作流
2. `平台与账户` → `/platform`
   - 注册、登录与密码找回
   - 看板与模型分析
   - API Key
   - 临时素材
   - 使用与生成记录
   - 钱包、账单与账户安全
3. `开发指南` → `/api-basics`
   - 身份验证与 Base URL
   - 媒体输入
   - 异步任务
   - 错误与重试
   - 计费与用量
   - curl、Python 与 TypeScript 示例
4. `模型与能力` → `/models`
   - 模型选择矩阵
   - Seedance 2.0 / Fast
   - Grok Imagine 图片与视频
   - 输入能力、分辨率、时长与音频支持
5. `API 参考` → `/api-reference`
   - Models、Images、Videos、Seedance、Assets
   - 标准错误结构与公共约定
6. `帮助与更新` → `/help`
   - 按症状排障
   - 常见状态码
   - 下载问题
   - 联系支持
   - 更新日志

`/examples` 与 `/changelog` 路由继续保留。“示例”进入“开发指南”的阅读路径，“更新日志”进入“帮助与更新”的阅读路径，不再各占一个顶部菜单。

侧边栏按相同概念重新排序，使顶部导航、栏目入口页和具体文章使用一致的命名和顺序。

## 首页内容结构

首页按以下顺序呈现：

1. **首屏定位**
   - 标题说明 Molii 提供 AI 图片与视频接入能力。
   - 主操作指向五分钟快速开始，次操作指向 API 参考。
   - 显示统一鉴权、多模态和任务可追踪三个可信信号。
2. **真实 API 示例**
   - 使用占位 API Key 展示 Seedance 视频创建请求。
   - 示例不在浏览器执行，也不触发真实付费任务。
3. **三条接入路径**
   - 第一次使用：创建 Key 并完成首个请求。
   - 视频工作流：提交、轮询、下载与结算。
   - 已有系统：直接进入完整 API 参考。
4. **模型与能力**
   - Seedance 2.0 为主要模型卡片。
   - Seedance 2.0 Fast 与 Grok Imagine 作为补充入口。
   - 只展示选择模型所需的关键信息，详细参数和价格留在模型页。
5. **异步任务完整链路**
   - 提交一次、按间隔轮询、获取结果、核对最终费用。
   - 明确付费 POST 不应自动重试。
6. **深入资源**
   - 生产接入清单。
   - 媒体输入、临时素材、错误处理与语言示例入口。

## 栏目入口页内容标准

每个栏目入口页使用 5–8 个有实际信息的章节，不以字数堆砌内容。入口页负责回答“这是什么、如何选择、从哪里开始、下一步去哪”，具体操作和参数细节通过子页面维护。

### `/quick-start`

- 完成目标与预计步骤
- 接入准备清单
- 获取并安全保存 API Key
- 第一张图片的完整请求
- 关键响应字段解释
- 视频任务与轮询入口
- 下一步阅读路径

### `/platform`

- 平台能力地图
- 账户生命周期
- 看板和模型分析
- API Key 管理
- 临时素材工作流
- 生成记录与费用查看
- 钱包账单与安全设置

### `/api-basics`

- 公共请求约定
- 环境和身份验证
- 媒体输入选择
- 异步任务生命周期
- 错误、超时和重试边界
- 预计费用与最终结算
- curl、Python 与 TypeScript 示例入口
- 生产上线清单

### `/models`

- 模型选择矩阵
- 图片、视频和编辑任务的适用模型
- 输入媒体支持
- 输出分辨率、比例、时长与音频能力
- Seedance 与 Grok 模型入口
- 参数和价格的权威查看位置

### `/examples`

- 按任务类型选择示例
- Seedance curl / Python / TypeScript
- Grok 图片、视频、轮询与下载
- 付费 POST、超时和下载安全提示
- 从示例跳转到相应 API 参考

### `/help`

- 按症状选择排障路径
- 登录、鉴权和限流问题
- 异步任务状态问题
- 媒体输入和下载问题
- 提交支持请求所需信息
- 不应发送的敏感信息
- 更新日志入口

`/api-reference` 现有内容已经完整，只补充更清晰的端点导航、同步与异步差异、错误结构和计费字段说明，不复制所有参数表。

## 实现结构

### 首页

- 新建 `docs-site/src/pages/index.tsx` 作为根路由。
- 新建 `docs-site/src/pages/index.module.css`，样式只作用于首页。
- 移除当前以 `slug: /` 占用根路由的 `docs-site/docs/index.mdx`，避免重复路由。
- 首页使用 Docusaurus `Layout`、`Link` 和现有主题变量，保留全站导航、搜索和页脚。
- 不新增 UI 框架、外部图片、远程字体或运行时接口请求。

### 内容和导航

- 扩充 `quick-start.md`、`platform.md`、`api-basics.md`、`models.md`、`examples.md` 与 `help.md`。
- 调整 `docusaurus.config.ts` 的顶部导航为六个已确认栏目。
- 调整 `sidebars.ts` 的分组顺序和标签，使其与顶部导航一致。
- 保留现有子页面和公开路由。

### 组件边界

首页页面负责静态内容和布局，不承载业务数据。重复卡片和步骤使用同文件内的静态数据数组渲染；只有当一段结构在多个页面复用时才提取独立组件。栏目入口页继续使用 Markdown/MDX，避免为了排版引入无意义的 React 抽象。

## 数据流与错误处理

所有首页和栏目内容在构建时生成，没有运行时 API 数据流。模型、端点和能力来自仓库中已有文档与已实现的公共接口。

- Docusaurus 在构建时对无效 Markdown 链接、图片、锚点和重复路由直接失败。
- 首页代码示例使用 `$MOLII_API_KEY` 等明确占位符，不包含真实密钥。
- 页面不自动执行代码，不请求付费接口，不加载上游媒体。
- 不在首页复制易变化的具体价格；价格只指向现有模型说明和平台模型广场。
- 任何模型能力摘要都必须能追溯到现有文档，避免入口页与参数页冲突。

## 响应式与可访问性

- 桌面端保持 `12px` 根字号，`996px` 及以下保持 `14px`。
- 首页在桌面使用双栏首屏和多列信息卡，在移动端改为单列。
- 顶部导航在移动端继续使用 Docusaurus 菜单，不通过页面 CSS 重新实现全站导航。
- 使用语义化标题、段落、列表、链接和代码块。
- 所有可操作项具备可见焦点状态和足够点击区域。
- 不使用横向页面滚动承载核心内容；代码块可在自身容器内横向滚动。
- 保持浏览器缩放，不限制用户放大页面。

## 测试与验收

### 自动化测试

- 浏览器测试验证根路由渲染自定义首页的六个主要模块。
- 浏览器测试验证顶部导航只有六个已确认栏目，并检查每个目标 URL。
- 浏览器测试在 `1440×900` 和 `390×844` 视口检查：首页无横向溢出，桌面内容高度超过两个视口，移动端内容完整可访问。
- 浏览器测试验证六个栏目入口页包含主要章节、子页面入口和下一步路径。
- 保留 Serif 正文字体、等宽代码字体和 `12px`／`14px` 响应式字号测试。
- 更新现有“禁止自定义首页”契约，使其允许根路由页面，同时继续禁止内页主题被自定义样式覆盖。

### 质量门

- `bun test`
- 禁用词检查
- 敏感信息扫描
- Docusaurus 生产构建
- 内部链接与锚点检查

### 视觉验收

- 首页和每个顶部栏目入口页在桌面与移动端检查。
- 验证导航、搜索、侧边栏、目录、代码块和表格无重叠、截断或页面级横向溢出。
- 验证首页视觉层级与已确认的高保真方案一致。
- 验证浏览器控制台没有新增错误或警告。

### 部署验收

- 将生产构建同步到现有 `Application Support/molii-docs/site`。
- 重启 `io.molii.docs`。
- 验证 `http://127.0.0.1:3100/` 返回 HTTP 200，并展示新首页和六项导航。

## 非目标

- 不修改后端 API、数据库、Redis、计费逻辑或用户平台页面。
- 不增加在线 API 调试器、SDK 生成器或交互式付费请求。
- 不重写所有具体 API 参数页。
- 不删除原有公开 URL 或受保护的 New API（QuantumNous）归属信息。
