# 模型概览能力区域重设计

## 背景

当前 LLM 模型详情的概览区域将规格、能力、模态和来源拆成多张薄卡。输入输出模态重复出现，说明文字与数值层级接近，来源和验证时间又占据模型信息的大单元格，导致详情抽屉纵向过长且缺乏重点。

## 设计目标

1. 定价继续作为概览的第一主要信息块，布局与计费逻辑保持不变。
2. 定价下方使用一张整合式“模型能力”卡。
3. 模型规格、输入输出模态和功能能力只出现一次。
4. 数据来源与验证时间作为辅助信息，不与核心规格争夺视觉权重。
5. 保持窄屏和桌面抽屉均可读。

## 页面结构

### 模型能力卡

模型能力卡由三部分组成：

1. **核心规格**
   - 上下文窗口
   - 最大输出
   - 发布日期或知识截止日期；没有数据时不展示空项
   - 桌面最多三列，窄屏自动两列或单列

2. **输入输出模态**
   - 使用一行明确展示“输入 文本 → 输出 文本”
   - 从原快速规格区域移除模态，避免重复

3. **有效能力**
   - 流式输出
   - 系统提示词
   - 推理
   - 工具调用
   - 结构化输出
   - 使用带图标或状态标识的规整能力项，不使用当前零散标签堆叠

卡片底部显示弱化的辅助说明：

`数据参考 models.dev · Molii 验证于 2026-08-13`

来源或日期缺失时，只展示存在的部分；两者都缺失时不展示辅助说明。

### 模型信息卡

模型信息卡仅保留业务相关字段：

- 提供商
- 计费类型
- 分组
- 端点
- 参数规模或标签仅在存在时展示

来源与验证时间从模型信息卡移除。

## 视觉规则

- 使用现有 `Card`、border、muted 和排版变量，不新增独立视觉体系。
- 核心数值比标签更突出；删除“最大输入窗口”“单次响应最大 Token 数”等重复解释。
- 能力项保持一致高度和对齐，不使用彩色营销标签。
- 模型能力卡内部使用留白和细分隔线形成层级，避免多张嵌套卡。
- 不增加动画，不改变详情抽屉宽度。

## 数据与兼容性

- 继续使用 `/api/pricing` 已返回的 `context_length`、`max_output_tokens`、`knowledge_cutoff`、`release_date`、`input_modalities`、`output_modalities`、`capabilities`、`metadata_source` 和 `metadata_verified_at`。
- 不在前端请求 models.dev。
- 不修改模型目录、能力判定和价格数据。
- 新布局仅用于通用 LLM 详情；Seedance 和 Grok 继续走现有专属组件。

## 测试

- 新增 LLM 模型能力卡组件测试，验证规格、模态、能力和来源说明。
- 验证模态只展示一次。
- 验证缺失可选字段不会出现空白占位。
- 验证来源和验证时间不再出现在模型信息卡。
- 运行模型广场测试、TypeScript 类型检查和本次文件静态检查。
- 不执行生产构建。
