# 模型定价币种统一设计

**日期：** 2026-09-30
**状态：** 待用户确认
**范围：** 管理员模型定价、计费表达式、额度扣费、模型广场与消费记录

## 1. 目标

平台将“供应商原始计价币种”“内部额度结算币种”和“用户界面显示币种”明确分开：

- 管理员可直接按供应商原始币种维护价格，首期支持 `USD` 与 `CNY`；
- `models.billing_currency` 表示模型价格及计费表达式数字所采用的**原始计价币种**；
- 平台内部继续以 USD 等值额度结算，避免重做现有额度、分组倍率和充值体系；
- 用户界面始终遵循平台显示币种。当前平台配置为 CNY，因此模型价格、余额、消费日志、账单详情和试算结果全部显示人民币；
- 每次请求冻结原币种、汇率和表达式，后续修改配置不改变该请求的结算与历史解释。

当前开发环境的基准配置为：

```text
平台显示币种：CNY
1 USD = 7 CNY
充值价格：7 CNY / USD 额度
```

`usd_exchange_rate` 与充值 `Price` 当前都为 7，但两者语义独立：前者用于模型成本换算，后者用于购买额度。

## 2. 核心语义

### 2.1 三种金额

每次计费都区分以下三个值：

| 名称 | 含义 | 示例 |
|---|---|---|
| 原币种金额 | 表达式或专用价格规则算出的供应商价格 | DeepSeek 输入价 `¥2 / 1M Token` |
| USD 等值成本 | 原币种金额换算后的内部结算成本 | `¥2 ÷ 7 = $0.285714` |
| 用户显示金额 | 按平台显示币种展示给用户的金额 | 当前显示 `¥2` |

`billing_currency` 不再决定用户看到 `$` 还是 `¥`，只决定表达式数字如何解释以及如何换成内部 USD 等值成本。

### 2.2 换算公式

汇率定义为：

```text
exchange_rate = 每 1 USD 对应的 CNY 数量
```

计算规则：

```text
USD 原价：cost_usd = source_cost
CNY 原价：cost_usd = source_cost / exchange_rate

平台显示 CNY：
  USD 原价：display_cost = source_cost * exchange_rate
  CNY 原价：display_cost = source_cost
```

分组倍率在币种归一化之后应用：

```text
final_quota = round(cost_usd * quota_per_unit * group_ratio)
```

这样可以保证同一分组倍率对 USD 与 CNY 模型具有相同语义。

### 2.3 示例

| 模型原币种 | 表达式价格 | 人民币展示 | 内部扣费 |
|---|---:|---:|---:|
| USD | `$5 / 1M Token` | `¥35 / 1M Token` | `$5` 等值额度 |
| CNY | `¥2 / 1M Token` | `¥2 / 1M Token` | `$2/7` 等值额度 |

充值价格为 `¥7 / USD` 时，上述 CNY 模型的 `¥2` 成本最终对应用户余额减少 `¥2`，不会被再次乘以 7。

## 3. 计费模式边界

### 3.1 计费表达式

计费表达式的数字按模型的 `billing_currency` 解释。

普通 Token 表达式先把表达式结果换成实际原币种金额，再归一化为 USD：

```text
source_cost = expression_output / 1,000,000
cost_usd = normalize(source_cost, billing_currency, exchange_rate)
```

按次表达式、任务表达式和已经自行除以一百万的表达式直接得到实际原币种金额：

```text
source_cost = expression_output
cost_usd = normalize(source_cost, billing_currency, exchange_rate)
```

表达式中的阶梯、峰谷、缓存、图片、音频等条件仅决定 `source_cost`，不参与币种换算。

### 3.2 Seedance 价格页

Seedance 2.0 标签页继续保留，管理员仍只维护该页面的人民币价格矩阵。保存后系统继续自动生成相应模型的任务计费表达式。

这些模型的元数据必须为 `billing_currency=CNY`。生成表达式得到人民币成本后，统一换成 USD 等值额度结算。现有“平台币种与 USD 1:1”的特殊约定废止。

### 3.3 Grok 专用价格

Grok 图片与视频目前使用专用价格矩阵和专用计费快照。其矩阵继续按 CNY 维护，但专用计算器必须调用与表达式相同的币种归一化组件，不能再把人民币数字按 USD 1:1 扣费。

异步任务提交、轮询完成和差额结算均使用提交时冻结的币种与汇率。

### 3.4 旧倍率和固定价格模式

旧 `ModelRatio`、`CompletionRatio` 和 `ModelPrice` 模式不携带原币种信息，继续按现有 USD 等值语义运行。管理员界面明确标注其为兼容模式，不允许仅通过修改 `billing_currency` 改变旧倍率模式的扣费。

需要按 CNY 维护的新价格必须使用计费表达式或已经接入统一金额上下文的专用价格页。

这一限制避免历史倍率配置在升级后被意外除以 7。

## 4. 统一金额上下文

后端新增一个不依赖具体计费模式的金额上下文，建议结构为：

```go
type BillingMoneyContext struct {
    SourceCurrency string  // USD or CNY
    CNYPerUSD      float64 // 提交时冻结；USD 模型也记录，供统一展示审计
}
```

并提供唯一的转换入口：

```go
NormalizeSourceCost(sourceCost, moneyContext) (costUSD, error)
```

规则：

- `sourceCost` 必须是有限、非负数；
- `SourceCurrency` 只接受 `USD`、`CNY`；
- CNY 模型要求 `CNYPerUSD > 0` 且为有限数；
- 缺少模型元数据时，为兼容旧模型默认 `USD`；
- 已存在但币种非法时拒绝计费，不回退为 USD；
- 不允许任何计费路径自行复制换算公式。

模型映射场景使用最终的**计费模型名**解析原币种，而不是请求模型名或上游展示模型名。

## 5. 请求快照与历史审计

### 5.1 表达式快照

`BillingSnapshot` 增加：

```text
source_currency
cny_per_usd
estimated_source_cost
estimated_cost_usd
```

实际结算结果增加：

```text
actual_source_cost
actual_cost_usd
```

快照在预扣时写入；流式完成、自动分组重试和实际用量结算只读取快照，不重新读取当前汇率或当前币种。

### 5.2 专用任务快照

Seedance、Grok 等异步任务把相同金额上下文保存到持久化 `BillingContext`。服务重启或数小时后任务完成时，仍使用提交时的汇率。

### 5.3 日志字段

消费日志的 `other` 公共审计字段增加：

```text
source_currency
source_cost
cny_per_usd
cost_usd
display_currency
display_cost
```

现有 `quota` 与内部最终成本语义保持不变，避免破坏统计与订阅逻辑。新增字段用于后台追溯，不用浮点金额反推额度。

用户端只展示平台币种金额；管理员详情可同时查看原币种金额、换算汇率、USD 等值成本和最终额度。

## 6. 管理员模型定价

### 6.1 编辑语义

`/system-settings/billing/model-pricing` 的币种控件改为实际配置项，名称为“原始计价币种”，选项为 `USD`、`CNY`。

- 输入框、阶梯摘要和表达式说明使用原币种符号；
- 页面固定提供“平台显示预览”，当前以 CNY 展示；
- 不再使用浏览器本地偏好伪装成模型币种配置；
- 帮助文字明确：原始计价币种决定表达式和实际扣费，平台显示币种决定用户看到的货币。

如果模型没有元数据记录，币种显示为兼容默认 USD，但保存前要求管理员先建立模型元数据，避免生成无法持久化的半配置状态。

### 6.2 原子保存

模型价格读取接口为每个条目返回 `billing_currency`。保存请求同时提交：

```text
model_name
expected_version
pricing
billing_currency
reset
```

版本摘要同时包含价格配置与币种，避免管理员 A 修改表达式、管理员 B 修改币种时互相覆盖。

同一个数据库事务内：

1. 锁定模型价格 Option 行；
2. 锁定精确模型名的元数据行；
3. 校验包含币种的版本；
4. 校验表达式与币种；
5. 写入价格 Option；
6. 写入模型 `billing_currency`；
7. 提交后刷新进程内价格和模型元数据缓存。

事务失败时两边都不写，不能出现“表达式已变、币种没变”或相反状态。

`reset` 恢复价格默认值，但不静默修改模型原始币种；币种必须由请求明确提交。

### 6.3 Seedance 标签页

Seedance 价格页继续作为该系列的唯一维护入口。保存价格矩阵时，事务同时保证四个 Seedance 模型存在且原始计价币种为 CNY，并发布生成的表达式。

通用模型价格页继续提示“价格由 Seedance 2.0 标签页维护”，不允许从两处竞争写入。

## 7. 用户端统一展示

所有面向用户的金额先转换为平台显示币种，不能直接根据模型 `billing_currency` 选择货币符号。

需要统一修复的界面包括：

- `/pricing` 模型卡片、详情、搜索结果和动态价格试算；
- 用户余额、充值后余额和可用额度；
- 使用日志、账单列表与账单详情；
- 图片、视频、任务模型的专用价格表；
- 管理员侧以“用户实际看到的价格”为目的的预览。

当前平台显示 CNY 时：

- USD 原价先乘 `usd_exchange_rate` 再显示 `¥`；
- CNY 原价直接显示 `¥`；
- 不再因为 `billing_currency=USD` 而向用户显示 `$`。

管理员编辑区中的原币种输入和审计字段是唯一可以同时出现 USD 与 CNY 的位置。

`Price` 仅用于充值额度售价或已有“按充值价格展示”的明确功能，不代替 `usd_exchange_rate` 解释供应商原价。

## 8. 汇率与失败策略

汇率继续由管理员在“货币与展示”中维护，不自动抓取外部市场汇率。

“宁可多收，不少收”通过管理员维护一个保守的 `usd_exchange_rate` 实现，不在代码里私自增加百分比。代码必须使用保存的精确值并在请求快照中记录。

以下情况拒绝新的收费请求，并返回可定位的模型价格配置错误：

- CNY 模型的汇率为零、负数、NaN、Infinity 或缺失；
- 模型币种不是 USD/CNY；
- 表达式结果不是有限、非负数；
- 专用价格路径无法生成完整金额快照。

不得以汇率 1 或 USD 作为静默降级，否则可能少收或多收。

已经预扣的请求如在实际表达式求值时失败，沿用现有安全策略保留预扣，并在日志中记录失败原因；币种快照仍保留。

## 9. 兼容与迁移

### 9.1 数据库

复用现有 `models.billing_currency`，无需新增模型表字段。快照和日志字段进入现有 JSON 结构，避免一次性数据库迁移。

### 9.2 默认行为

- 没有模型元数据的历史表达式默认 USD；
- 旧倍率/固定价格继续按 USD 等值；
- 已标记 CNY 的表达式和专用价格从发布本功能起按 CNY 正确换算；
- 不自动把所有国内厂商模型改成 CNY，必须依据实际维护价格逐个确认。

### 9.3 首批校准

发布前审计所有 `billing_currency=CNY` 的模型，至少覆盖：

- `deepseek-flash`；
- `deepseek-v4-pro-202606`；
- Seedance 2.0/2.5 系列；
- Grok Imagine 图片与视频；
- 现有 MiniMax、Qwen CNY 模型。

审计清单记录价格来源、计费模式、表达式单位、原币种和预期人民币结果。发现仍按 USD 数字维护的模型先改元数据或表达式，再启用新换算，避免上线瞬间改变 7 倍。

## 10. 测试与验收

### 10.1 后端单元测试

- USD、CNY 两种原币种的转换；
- 无效币种、无效汇率和无效金额拒绝；
- Token、固定按次、任务表达式的单位转换顺序；
- 分组倍率在 USD 归一化后应用；
- 预扣和实际结算使用同一个冻结汇率；
- 汇率在请求过程中修改不影响该请求；
- 自动分组重试只更新分组倍率，不更新币种和汇率；
- 模型映射使用计费模型币种；
- Seedance 和 Grok 不发生重复换算；
- 旧倍率模型不因 `billing_currency=CNY` 被除以 7。

### 10.2 API 与事务测试

- 模型价格接口返回原始计价币种；
- 价格与币种一次保存成功；
- 任一写入失败时整体回滚；
- 版本冲突能检测只改币种的并发写；
- Reset 不隐式改变币种；
- Seedance 矩阵、四个表达式和 CNY 元数据原子发布。

### 10.3 前端测试

- 平台为 CNY 时，USD 和 CNY 模型都显示 `¥`；
- USD 模型乘 7，CNY 模型不换算；
- 管理员输入框显示原币种，预览显示平台币种；
- 修改原币种会进入未保存状态并持久化；
- `/pricing?search=deepseek` 中 Flash 与 Pro 都显示正确人民币；
- 余额、日志、账单与专用任务价格均不再泄漏美元符号。

### 10.4 端到端验收样例

在汇率 7、分组倍率 1 下：

```text
USD 表达式：tier("base", p * 5)
用量：1,000,000 输入 Token
预期：展示 ¥35；内部成本 $5；用户人民币额度减少 ¥35

CNY 表达式：tier("base", p * 2)
用量：1,000,000 输入 Token
预期：展示 ¥2；内部成本 $0.285714...；用户人民币额度减少 ¥2
```

再以分组倍率 1.2 重跑，人民币最终成本分别为 `¥42` 与 `¥2.4`。

## 11. 发布顺序

1. 加入统一金额上下文、快照字段和后端测试，但保持历史 USD 默认；
2. 接入普通表达式、任务表达式、Seedance 与 Grok 专用计费；
3. 扩展模型价格读写 API并完成原子保存；
4. 修复管理员编辑器与所有用户端人民币展示；
5. 审计并校准现有 CNY 模型，重点验证 DeepSeek Flash/Pro；
6. 在 dev 环境跑模拟用量和实际小额请求，核对余额、日志与数据库额度；
7. 推送 `develop` 触发 CI/CD，部署后复查公开价格页与真实扣费。

在完成第 5 步审计前，不允许直接把新换算逻辑部署到生产环境。

## 12. 不采用的方案

### 只修前端符号

会让页面看起来是人民币，但 CNY 表达式仍按 USD 扣费，实际多收 7 倍，不能采用。

### 把所有表达式统一改写为 USD

管理员每次维护人民币供应商价格都要手工除以汇率，汇率变化后还要批量改表达式，容易出错且无法审计，不采用。

### 用充值 Price 作为模型汇率

充值售价可以包含支付成本或促销策略，不等同于模型成本换算汇率，不采用。

### 全平台改成人民币原生额度

会同时影响充值、订阅、分组倍率、历史额度、统计和大量接口，迁移风险远高于当前需求。首期保留 USD 等值内部额度。
