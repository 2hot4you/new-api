# Grok 异步视频最终消费日志设计

## 目标

让 Molii Grok Imagine API 的所有异步视频任务只在终态产生一条用户可见日志：成功任务写一条最终消费日志，失败或过期任务写一条错误日志。提交预扣、成功差额补扣/退还和失败退款继续作为内部资金动作执行，但不再形成用户可见的消费或退款流水。

覆盖范围：

- `grok-imagine-video`
- `grok-imagine-video-1.5`
- 文生视频
- 图生视频
- 视频编辑

不改变同步 Grok 图片日志、Molii AIGC/Seedance 日志或其他渠道的异步日志行为。

## 选定方案

采用后端终态日志，而不是仅在前端隐藏中间流水，也不更新提交阶段的旧日志。

原因：

- 前端隐藏不能消除数据库中的重复流水和用量统计。
- 更新旧日志需要跨节点关联和恢复逻辑，终态 CAS 已经提供更可靠的单写入口。
- 当前 Molii AIGC 异步任务已有“提交不记账、终态统一记账”的成熟模式，可以模块化复用。

## 资金与日志分离

资金生命周期保持不变：

1. 提交前校验余额并预扣估算额度。
2. 上游接受任务后持久化任务和价格快照。
3. 成功后根据实际结果补扣或退还差额。
4. 失败或过期后退还全部预扣。

用户日志生命周期调整为：

1. 提交成功：不写消费日志，不更新用户请求数、用户已用额度或渠道已用额度统计。
2. 任务成功：终态 CAS 获胜者完成差额结算后写一条最终消费日志，并使用最终额度更新统计。
3. 任务失败或过期：终态 CAS 获胜者完成内部退款后写一条零额度错误日志。
4. 内部补扣、差额退还和失败退款均不写用户可见流水。

最终消费日志的 `quota` 必须等于任务结算后的 `task.Quota`；日志总价以 `task.Quota / QuotaPerUnit` 为最终事实来源。

## 发布兼容

在 `TaskBillingContext` 新增 `final_usage_log_only` 标记。只有新版本提交的 Grok 视频任务设置该标记。

- 新任务：使用终态单日志流程。
- 发布前已存在的进行中任务：保持旧日志行为，避免已经写过提交日志后又补写最终日志。
- Molii AIGC 继续沿用现有终态日志机制，不依赖该标记。
- 历史日志不做删除、回写或迁移。

该字段存储在现有 `private_data` JSON 中，不需要数据库表结构迁移。

## Grok 视频计费快照

在 `TaskBillingContext` 中持久化版本化的 Grok 视频计费快照，并在最终日志的 `other.grok_video_billing` 中输出公开副本。

V1 字段：

```json
{
  "version": 1,
  "model": "grok-imagine-video",
  "operation": "video_edit",
  "input_type": "video",
  "requested_duration_seconds": 0,
  "estimated_duration_seconds": 8.7,
  "actual_duration_seconds": 6,
  "requested_resolution": "",
  "estimated_resolution": "720p",
  "actual_resolution": "480p",
  "aspect_ratio": "",
  "input_image_count": 0,
  "video_input_billed_seconds": 6,
  "output_unit_price": 0.05,
  "image_input_unit_price": 0.002,
  "video_input_unit_price": 0.01,
  "output_cost": 0.3,
  "image_input_cost": 0,
  "video_input_cost": 0.06,
  "subtotal": 0.36,
  "group_ratio": 1,
  "final_cost": 0.36
}
```

约束：

- `operation` 仅允许 `text_to_video`、`image_to_video`、`video_edit`。
- `input_type` 仅允许 `text`、`image`、`video`。
- 价格在提交时快照，任务完成期间管理员改价不能影响在途任务。
- 视频编辑的实际时长和分辨率由终态结果及现有官方费率识别逻辑确定。
- 图生视频按实际发送给上游的一张图片计输入费；不记录图片 URL 或 `file_id`。
- 视频编辑只记录计费秒数；不记录视频 URL、`file_id` 或上游任务 ID。
- `final_cost` 从已结算额度换算，避免浮点取整后日志金额与真实扣费不一致。

## 公式

文生视频：

```text
(输出单价 × 实际输出秒数) × 分组倍率 = 最终总价
```

图生视频：

```text
(输出单价 × 实际输出秒数 + 图片输入单价 × 输入图片数) × 分组倍率 = 最终总价
```

视频编辑：

```text
(输出单价 × 实际输出秒数 + 视频输入单价 × 视频输入计费秒数) × 分组倍率 = 最终总价
```

日志同时保留各项小计。零价格必须作为有效配置展示，不能回退为模型锚定价。

## 后端结构

### 提交阶段

- Molii Grok 任务在创建 `TaskBillingContext` 时设置 `final_usage_log_only=true` 并保存 Grok 视频价格快照。
- `LogTaskConsumption` 跳过这些新任务，因此不产生提交消费日志和预估统计。
- 预扣与 Token/订阅资金来源处理不变。

### 轮询终态

- 适配器在成功解析终态时更新快照中的实际时长、实际分辨率、单价和各项小计。
- 差额结算只调整钱包/订阅与 Token 额度，不写中间消费或退款日志。
- 终态 CAS 获胜后统一记录成功或失败日志，防止多轮询器重复记录。
- 最终成功日志写入 `is_task`、公开 `task_id`、`request_path` 和 `grok_video_billing`；不得写入结果 URL、上游任务 ID、渠道密钥或原始轮询响应。

### 统计

- 成功时用最终 `task.Quota` 调用一次用户与渠道统计更新。
- 失败任务不增加成功请求数或已用额度。
- 差额结算不再单独更新统计，避免最终日志再次累计。

## 前端展示

新增与 Grok Image 一致的 `GrokVideoBillingCard`：

- 模型 ID
- 操作类型
- 输入类型
- 请求、预估和实际时长
- 请求、预估和实际分辨率
- 画面比例
- 输入图片数或视频输入计费秒数
- 输出、图片输入和视频输入单价
- 各项小计、分组倍率、计费公式和最终总价

当前 V1 日志使用结构化卡片并隐藏通用 Token/按次锚定价详情。模型属于 Grok 视频但缺少 V1 快照的历史日志降级为“模型 ID + 最终扣费 + 历史明细不可用”。列表摘要显示实际分辨率、实际时长与操作类型。

中英文文案同时补齐。普通用户和管理员看到相同计费公式；管理员专属字段继续遵循现有 `admin_info` 过滤规则。

## 错误处理与幂等

- 只有任务状态持久化 CAS 成功的轮询器可以写终态日志。
- 差额资金调整失败时不写最终成功消费日志，保留后端错误以便重试或人工对账。
- 最终日志写入失败不能再次调整资金；依靠现有终态状态和可观测错误处理，禁止重复扣费。
- 失败退款成功后写一条脱敏错误日志；退款失败时保留任务额度标记，不伪造已退款状态。

## 测试

后端测试覆盖：

- 新 Grok 任务提交时不写消费日志或统计。
- 成功且无需调整、成功补扣、成功差额退还均只产生一条最终消费日志。
- 失败和过期只产生一条错误日志，无退款日志。
- 文生、图生、视频编辑三种公式和价格快照。
- 两个 Grok 视频模型。
- 终态 CAS、多次轮询和旧任务兼容，不重复日志、不重复统计。
- 零价格、分组倍率和额度取整。
- 日志不含输入媒体地址、上游 ID 或渠道密钥。

前端测试覆盖：

- V1 解析器的完整字段校验与错误降级。
- 三种操作的公式。
- 当前日志卡片和历史日志降级展示。
- 通用 Token/锚定模型价格在 Grok 视频日志中隐藏。

验证命令包括 `go test ./...`、Go 构建、`gofmt`、前端类型检查、相关前端测试、前端构建和 `git diff --check`。
