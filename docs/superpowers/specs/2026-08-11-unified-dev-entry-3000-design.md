# New API 统一 3000 本地开发入口设计

## 目标

本地开发时只访问 `http://127.0.0.1:3000`。Go 后端继续监听 3000，前端源码仍由 Rsbuild 开发服务器提供热更新，但其内部端口不再作为用户入口，也不执行前端生产构建。

## 架构

- 新增显式开发配置 `FRONTEND_DEV_SERVER_URL`，本地默认指向 `http://127.0.0.1:3001`。
- Go 路由优先注册现有 `/api`、`/v1`、视频等后端接口。
- 启用开发配置后，后端对未匹配的页面、脚本、样式及 HMR 请求使用标准 HTTP 反向代理转发到 Rsbuild。
- 未匹配的后端命名空间（至少 `/api`、`/v1`、`/assets`、`/mj`、`/pg`）不会转发，以避免接口错误被前端吞掉或形成代理循环。
- 未设置开发配置时保持现有行为：主节点使用内嵌 `web/dist`，其他既有 `FRONTEND_BASE_URL` 行为不变。

## 本地运行

- Go API：`127.0.0.1:3000`
- Rsbuild 内部服务：`127.0.0.1:3001`
- 浏览器统一入口：`http://127.0.0.1:3000`
- `make dev-api` 自动注入开发前端地址；`make dev-web` 启动内部 Rsbuild 服务。

## 错误与安全

- 前端开发服务未启动时，页面请求返回明确的 `502 Bad Gateway`，API 仍可独立工作。
- 代理目标只来自进程环境变量，不来自用户请求或数据库。
- 反向代理不改变现有 API 鉴权、Cookie、Session、CORS 或生产部署逻辑。

## 测试与验收

- 路由测试覆盖页面/静态资源代理、API 命名空间不代理、开发服务不可达返回 502。
- Go 测试和前端类型检查通过。
- 不运行生产构建。
- 启动两个本地进程后，在 `127.0.0.1:3000/channels` 编辑 Molii Grok Imagine API，确认管理凭据字段可见且页面热更新服务正常。
