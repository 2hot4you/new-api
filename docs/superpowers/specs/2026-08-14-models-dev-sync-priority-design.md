# models.dev 同步优先级设计

## 目标

手动同步 models.dev 时让管理员明确选择数据优先级，避免无法判断同步是否会覆盖本地模型元数据。

## 同步模式

### 本地优先

请求值为 `local_first`，也是后端默认值。同步只补充本地为空的模型元数据，已有内容保持不变。没有携带同步模式的旧客户端继续使用该行为。

### models.dev 优先

请求值为 `models_dev_first`。同步覆盖 models.dev 能提供的全部模型元数据：

- 模型简介
- 厂商归属
- 模型图标
- 上下文长度
- 最大输出 Token
- 输入和输出模态
- 能力标签
- 发布日期
- 知识截止时间
- 元数据来源和最近验证时间

该模式不修改 models.dev 不拥有的数据：Molii 本地价格、渠道、模型启用状态、路由和分组配置。

## 用户界面

现有 models.dev 同步弹窗新增两个单选卡片。本地优先作为默认选项；models.dev 优先显示覆盖提醒。确认按钮保持为“立即同步”，提交时携带 `sync_mode`。同步成功提示继续展示新增、更新和跳过数量。

## 后端接口

`POST /api/models/sync_upstream` 接收 JSON：

```json
{
  "sync_mode": "local_first"
}
```

后端只接受 `local_first` 和 `models_dev_first`。缺失值按 `local_first` 处理，未知值返回稳定的参数错误，不启动外部请求或数据库写入。

自动同步继续使用 `local_first`，不会因为手动同步新增覆盖能力而改变后台任务行为。

## 数据处理

两个模式共用 models.dev 下载、可信厂商匹配和字段规范化逻辑。差异只存在于事务内生成数据库更新字段的策略：

- `local_first` 调用“填充空字段”策略。
- `models_dev_first` 调用“覆盖受支持元数据字段”策略。

厂商同步使用 models.dev 的可信 provider 映射到 Molii 厂商记录；如厂商记录不存在则按项目现有厂商创建方式补建。任何模式都不得写入计费和渠道表。

## 错误与安全

- models.dev 拉取失败时不写入任何模型元数据。
- 单个模型无法可信匹配时跳过并计入结果。
- 未知同步模式在请求校验阶段直接拒绝。
- 覆盖操作在数据库事务中完成，失败时回滚。
- 返回给前端的错误保持稳定且不暴露上游响应内容。

## 测试

- 后端测试本地优先只补空值。
- 后端测试 models.dev 优先覆盖全部受支持元数据字段。
- 后端测试两种模式都不修改价格、启用状态、渠道和路由配置。
- 后端测试缺失模式使用本地优先，未知模式被拒绝。
- 前端测试默认选中本地优先、切换后提交正确值并显示覆盖提醒。
- 运行完整 Go 测试、前端类型检查、i18n 检查和本地页面验证，不执行生产构建。
