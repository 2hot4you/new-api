# models.dev 模型元数据多语言同步设计

## 目标

New API 继续以 models.dev 作为唯一外部模型元数据来源，同时提供管理员可见的手动同步入口。models.dev 返回的英文模型简介由开发者人工翻译为简体中文和繁体中文，并通过现有 Web i18n 体系展示；运行时不调用任何翻译服务。

本设计只同步模型目录元数据。Molii 的模型价格、分组倍率、渠道映射、启用状态和自定义模型映射保持本地权威，不受元数据同步影响。

## 数据源与职责边界

- 自动同步和手动同步统一读取 models.dev 的公开模型目录。
- 删除旧 basellm.github.io“官方同步”数据源，避免两套来源互相覆盖。
- models.dev 提供模型 ID、英文名称、英文简介、上下文、输出上限、模态、能力、知识截止时间和发布日期等事实。
- New API 负责模型 ID 匹配、元数据保存、人工翻译键关联、冲突预览和缓存刷新。
- Web i18n 文件负责人工维护中文译文，不承担在线翻译。

## 模型匹配规则

同步只处理 New API 已启用或已登记的模型，不因 models.dev 目录新增条目而自动启用模型。

匹配顺序如下：

1. models.dev 模型 ID 与本地模型 ID 完全一致。
2. 在已确认的厂商范围内，使用去除厂商前缀后的模型 ID 精确匹配。
3. 对 MiniMax 等存在大小写差异的 ID，执行忽略大小写的精确匹配。

不做包含、前缀猜测或编辑距离匹配。多个候选同时命中时，该模型进入冲突列表并跳过写入。

## 数据模型与优先级

不新增数据库字段。`Model.Description` 继续保存管理员自定义简介或 models.dev 同步得到的英文简介。models.dev 英文简介本身同时作为 Web i18n 键和缺少译文时的回退文本，这与项目现有的英文原文键模式一致。

同步可更新以下目录字段：

- 空白 `description` 对应的 models.dev 英文简介
- 厂商关联与默认图标
- 上下文长度和最大输出 Token
- 知识截止时间和发布日期
- 输入、输出模态
- 推理、工具调用、结构化输出等能力
- 元数据来源和最近验证时间

同步永不修改以下业务字段：

- `description` 管理员自定义简介
- 模型价格、计费表达式和分组倍率
- 渠道、渠道模型映射和渠道密钥
- 模型启用状态、分组可用性和 Token 限制
- 管理员自定义端点及其他非目录配置

模型广场简介按以下顺序解析：

1. 读取非空 `description`。
2. 使用 `description` 在当前 Web locale 中查找人工译文。
3. 找不到译文时原样显示 `description`，因此 models.dev 英文原文会自然成为回退。
4. `description` 为空时，继续使用现有 `description_i18n_key` 兼容回退。

同步仍只填充空白简介，不覆盖管理员已有内容。对于由旧版 Molii 自动写入的已知默认简介，仅当内容与旧默认值完全一致时才允许迁移为 models.dev 英文原文；任何不同内容都视为管理员修改并保留。

## 人工翻译与语言回退

当前启用模型的 models.dev 英文简介作为 i18n 基准键写入所有 Web locale 文件。英文原文发生变化后，新原文会作为新键回退显示英文，旧中文译文不会错误套用；开发者审核后再补充新键的翻译。

- `en` 保留 models.dev 英文原文。
- `zh` 由开发者人工翻译为简体中文。
- `zh-TW` 由开发者人工翻译为繁体中文。
- `fr`、`ru`、`ja`、`vi` 暂时保留英文原文，保证键集合完整并提供稳定回退。

运行时不调用大模型、翻译 API 或第三方翻译服务。后续新增模型完成元数据同步后，允许先显示英文简介；开发者随后按批次补充中文译文并随代码发布。

翻译应保留模型名称、API 名称、参数名、Token 单位和行业术语，不擅自增加 models.dev 未提供的性能或能力承诺。

## 自动同步与手动同步

现有 models.dev 定时同步继续保留，使用统一的解析与写入服务。管理端模型页面增加明显的“同步 models.dev”按钮，不再隐藏在来源选择向导中。

手动同步流程：

1. 获取并校验 models.dev 目录。
2. 生成新增、更新、跳过和冲突预览。
3. 管理员确认后执行同步。
4. 返回更新数量、跳过数量、冲突列表和缺少中文翻译的模型列表。
5. 同步成功后刷新模型列表、模型元数据和模型广场定价缓存。

同步界面不再提供“官方源 / 配置源”选择，也不再提供上游语言选择。相关按钮、提示、成功消息和错误消息使用 Web 现有七种界面语言。

## 错误与安全边界

- HTTP 超时、非 2xx、响应超限、JSON 解析失败或空目录均使整次同步失败。
- 整次同步失败时不得清空或部分覆盖现有模型元数据。
- 单条模型字段非法时跳过该条并在结果中说明原因。
- models.dev 英文简介只作为显示文本处理，不解释为 HTML，不直接执行其中内容。
- 同步日志不记录密钥、Cookie 或用户凭据。
- 自动同步失败只记录告警并等待下次计划；手动同步返回可读错误，不影响现有模型调用。

## 配置与兼容性

保留可覆盖的 models.dev 目录 URL、同步开关、间隔、超时和响应大小限制。环境变量示例只提供公开 URL，不包含任何密钥。

本方案不增加数据库迁移。已有管理员简介不清空，只有与已知旧版默认值完全相同的系统简介才执行受控迁移。

旧 basellm 同步接口保留原路由以降低前端升级风险，但内部改为调用统一 models.dev 同步服务；前端不再显示旧来源名称。确认没有其他调用方后，可在后续上游同步中单独移除兼容路由。

## 测试与验收

后端测试覆盖：

- models.dev 响应解析与响应大小限制。
- 完整 ID、去前缀和大小写匹配。
- 歧义匹配拒绝和单条非法数据跳过。
- 管理员简介及计费、渠道、启用状态不被覆盖。
- 空目录和请求失败不产生部分写入。
- 自动同步与手动同步复用同一服务。
- 同步成功后相关缓存失效。

前端测试覆盖：

- 简介优先级：当前语言人工译文、原始简介回退、兼容 i18n key 回退。
- 管理员自定义简介没有翻译键时保持原样。
- `zh` 和 `zh-TW` 显示人工中文译文。
- 其他语言在缺少人工译文时显示英文。
- 手动同步按钮、预览、结果和错误状态。
- 七个 locale 文件包含相同同步界面键和模型简介键。

验收时只运行本地开发环境所需的定向 Go 测试、前端测试、类型检查、格式检查和接口验证，不进行 Docker、Cloudflare Pages、Vercel 或生产构建。
