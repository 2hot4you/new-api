# 模型广场本地元数据配置设计

日期：2026-08-15  
状态：已确认，待实施计划

## 1. 背景与目标

当前模型广场的公开资料来自数据库、内置模型目录以及 models.dev 同步结果，导致同一个模型存在多个事实来源。管理员难以判断页面最终采用哪份描述、能力或规格，新增模型也容易以资料不完整的状态公开。

本次改造将 `/models/metadata` 中的模型记录确立为模型广场公开资料的唯一人工事实源。管理员在模型列表中打开对应模型 ID 的右侧编辑抽屉，输入或选择固定字段；模型广场不再从 models.dev 或按模型 ID 写死的目录资料中补全内容。

目标：

- 模型资料只有一个可编辑来源。
- 模型资料允许先保存为草稿，资料完整后再显式发布。
- 模型资料、价格、渠道能力和运行性能保持独立边界。
- LLM、图片和视频模型使用同一套公共字段，并按模型类别执行条件校验。
- 新模型 ID 可以从渠道同步产生，但不会自动公开。

不在本次范围内：

- 改造现有计费表达式、分组倍率或视频/图片专用价格表。
- 改造渠道模型发现和渠道可达性逻辑。
- 将运行性能或使用日志写入模型元数据。
- 为尚未接入的音频、Embedding、Rerank 模型提前设计完整专用规格。

## 2. 数据边界

### 2.1 模型元数据负责的内容

`models` 表负责持久化模型广场的公开身份、介绍、模态、能力和静态规格。模型卡片、厂商分组、详情概览和能力区只读取这些持久化字段。

### 2.2 其他系统负责的内容

- 供应商名称、Logo 和介绍来自 `vendors` 表。
- 输入、输出、缓存、按次、分档及动态表达式价格来自现有计费配置。
- 可用分组和支持端点来自实际渠道能力。
- 延迟、吞吐量和成功率来自运行日志。
- Seedance、Grok 等特殊 API 请求结构继续由其 API 模板维护；公共参数可以引用模型元数据中的支持参数。

模型元数据不得重复保存价格、分组倍率、渠道绑定、实时性能或运行可达性。

## 3. 数据模型

继续使用现有 `models` 表，不建立第二张模型广场资料表。

### 3.1 现有公共字段

- `model_name`：API 模型 ID，必填且唯一。创建后不可在普通编辑流程中修改。
- `description`：中文简介，公开发布时必填。
- `icon`：模型专属 Logo，可空；为空时继承供应商 Logo。
- `vendor_id`：所属供应商，公开发布时必填，且供应商必须启用。
- `tags`：辅助搜索标签，可选。
- `context_length`：上下文长度。
- `max_output_tokens`：最大输出 Token。
- `knowledge_cutoff`：知识截止日期，可选。
- `release_date`：发布日期，公开发布时必填，格式为 `YYYY-MM-DD`。
- `input_modalities`：输入模态数组。
- `output_modalities`：输出模态数组。
- `capabilities`：能力数组。

### 3.2 新增字段

- `display_name`：公开展示名称，必填；模型 ID 仍作为独立的可复制标识显示。
- `description_en`：英文简介，可选。
- `marketplace_enabled`：是否允许在模型广场公开展示，默认关闭。
- `supported_parameters`：支持的公共 API 参数数组。
- `supported_resolutions`：支持的图片或视频分辨率数组。
- `supported_aspect_ratios`：支持的宽高比数组。
- `max_input_images`：图片编辑允许的最大输入图片数量。
- `output_formats`：图片返回格式数组，例如 `url`、`b64_json`。
- `min_duration`：视频最小时长，单位秒。
- `max_duration`：视频最大时长，单位秒。
- `reference_modalities`：视频生成支持的参考素材类型数组。

数组字段使用结构化 JSON 持久化，不使用逗号字符串。模型类别和资料完整度由服务端根据字段实时推导，不重复写入数据库。

遗留的 `metadata_source`、`metadata_verified_at` 可在兼容迁移期保留，但不再作为编辑入口或模型广场内容来源；模型广场展示实际更新时间。

## 4. 模型分类与完整性校验

### 4.1 类别推导

服务端按输出模态和能力推导主类别：

1. 输出包含 `video` 或具备 `video_generation`：视频模型。
2. 输出包含 `image` 或具备 `image_generation`：图片模型。
3. 输出包含 `audio` 或具备 `audio_generation`：音频模型。
4. 具备 `embeddings`：Embedding 模型。
5. 其余输出文本的模型：LLM。

视频模型可以同时输出音频，但主类别仍为视频。

### 4.2 所有公开模型的必填字段

- 模型 ID。
- 展示名称。
- 启用的供应商。
- 中文简介。
- 发布日期。
- 至少一个输入模态。
- 至少一个输出模态。
- 至少一个能力。

模型 Logo 允许为空并继承供应商 Logo；英文简介、知识截止日期和标签均为可选字段。

### 4.3 LLM 条件字段

- `context_length` 必须大于零。
- `max_output_tokens` 必须大于零且不得大于上下文长度。
- `supported_parameters` 至少包含一个已登记参数。
- 输入和输出必须包含 `text`。

支持参数采用受控选项，例如 `stream`、`temperature`、`top_p`、`max_tokens`、`tools`、`tool_choice`、`reasoning_effort` 和 `response_format`；未知参数不得通过自由文本进入公开契约。

### 4.4 图片模型条件字段

- `supported_resolutions` 至少一项。
- `supported_aspect_ratios` 至少一项。
- `output_formats` 至少一项。
- 具备 `image_editing` 时，`max_input_images` 必须大于零，且输入模态必须包含 `image`。
- 输出模态必须包含 `image`。

### 4.5 视频模型条件字段

- `supported_resolutions` 至少一项。
- `supported_aspect_ratios` 至少一项。
- `min_duration` 和 `max_duration` 必须大于零，且最小时长不得大于最大时长。
- 输出模态必须包含 `video`。
- `reference_modalities` 只能选择已登记的图片、视频或音频类型，并应是输入模态的子集。
- 视频任务在当前系统中固定为异步；管理界面只读展示该事实，不保存重复开关。

### 4.6 其他类别

音频、Embedding 和 Rerank 在本次仅使用公共字段。后续真正接入对应模型时，再通过独立设计增加其条件字段，不在本次表单中提前堆积未使用配置。

## 5. 发布规则

模型资料允许在任意完整度下保存为草稿。公开展示采用显式发布，而不是“字段填满后自动发布”。

模型出现在模型广场必须同时满足：

1. 模型状态启用。
2. `marketplace_enabled = true`。
3. 公共字段和所属类别的条件字段全部通过校验。
4. 供应商存在且启用。
5. 至少存在一个实际可用分组和一个实际支持端点。
6. 存在有效计费配置。

模型资料接口返回以下只读派生信息：

- `marketplace_category`：推导出的主类别。
- `marketplace_complete`：资料是否完整。
- `marketplace_missing_fields`：缺失或非法字段的稳定字段名数组。
- `marketplace_visible`：当前是否满足最终公开条件。
- `marketplace_blockers`：渠道、价格或供应商等动态阻断原因。

管理员尝试开启发布开关时，资料不完整则拒绝并列出缺失字段。已发布模型随后被保存为不完整资料时，保存操作成功，但服务端在同一事务中关闭 `marketplace_enabled` 并返回撤下原因。

渠道、分组或价格暂时不可用时不修改 `marketplace_enabled`，只令 `marketplace_visible` 变为 false；条件恢复后模型自动重新出现。

## 6. 管理界面

`/models/metadata` 列表中的每个模型 ID 保留右侧编辑入口，打开统一编辑抽屉。

### 6.1 模型广场资料

- 模型 ID：创建时输入，编辑时只读。
- 展示名称。
- 供应商选择。
- 模型 Logo，可清空以继承供应商 Logo。
- 中文简介。
- 英文简介。
- 发布日期、知识截止日期和标签。

### 6.2 模态与能力

- 输入模态多选。
- 输出模态多选。
- 能力多选。
- 支持参数多选。
- 根据推导类别动态显示 LLM、图片或视频规格字段。

### 6.3 发布状态

- 模型状态。
- “在模型广场展示”开关。
- 资料完整度。
- 缺失字段列表。
- 当前公开状态及动态阻断原因。

### 6.4 高级配置

原有名称匹配规则和自定义端点保留在默认折叠的高级区域。具体价格不在抽屉中重复编辑，只显示计费方式摘要并提供前往模型定价页面的入口。

所有选择器使用固定枚举及中文标签；后端仍执行同一套校验，不能只依赖前端表单。

## 7. 模型广场读取行为

- 模型卡片显示展示名称、模型 ID、供应商、简介、模态、主要能力、价格摘要、静态规格、发布日期和性能摘要。
- 厂商分组标题读取 `vendors` 表中的名称、Logo 和介绍。
- 模型详情概览读取相同元数据，不再按模型 ID 匹配前端或后端内置文案。
- 中文界面读取 `description`；英文界面优先读取 `description_en`，为空时回退中文；其他语言暂时回退中文。
- 排序以 `release_date` 从新到旧为主，缺少发布日期的草稿不允许发布。
- 计费、端点和性能继续来自各自的动态数据源。

## 8. 外部同步与内置目录处理

- 删除 models.dev 手动同步按钮、优先级选择弹窗、自动同步任务和相关用户文案。
- 删除模型广场运行时按模型 ID读取 `catalogModelProfiles`、`catalogVendorProfiles` 等内置资料的兜底行为。
- 保留从渠道获取模型 ID 的能力。新发现的模型只建立未发布草稿，不补写虚构简介或能力。
- 供应商资料继续通过供应商管理维护。
- 不删除或改造 New API 上游原有的渠道模型同步能力，只移除本项目新增的 models.dev 元数据同步职责。

## 9. 迁移与兼容

- 新增字段使用向前兼容的数据库迁移并提供 PostgreSQL 显式迁移文件。
- 现有 `description`、厂商、模态、能力和规格原样保留。
- `display_name` 初始回填为 `model_name`，避免现有页面标题为空。
- 迁移时根据数据库中已有资料执行一次完整性检查。当前已在模型广场展示且通过新规则的模型设置为 `marketplace_enabled = true`；未通过的模型保留为草稿。
- 迁移不修改任何价格、渠道、分组、日志或账户数据。
- 在删除内置目录兜底前，先完成数据库回填并通过公开模型列表对比，避免已有模型资料消失。

## 10. 错误处理

- 字段校验错误返回稳定字段名和中文说明。
- 发布失败返回全部缺失字段，而不是只返回第一个错误。
- 供应商停用或删除后，关联模型不再公开，但模型资料不丢失。
- 非法数组值、日期、时长范围和数值边界在服务端拒绝。
- 模型广场不向普通用户暴露管理配置、渠道 ID 或内部阻断细节；普通用户只能看到当前可用模型。

## 11. 测试与验收

后端测试覆盖：

- 公共字段和分类条件字段校验。
- LLM、图片、视频类别推导。
- 草稿保存、显式发布、自动撤下和动态恢复。
- 供应商、价格、分组及端点交集。
- 中文、英文和其他语言的简介回退。
- 旧数据回填与迁移幂等。
- 新渠道模型只生成草稿。
- 公开定价接口不再读取内置目录资料。

前端测试覆盖：

- 编辑抽屉的字段分区和动态条件字段。
- 完整度、缺失字段和发布阻断提示。
- 模型 ID 编辑态只读。
- Logo 继承、语言回退、厂商分组和发布日期排序。
- 模型广场卡片与详情只消费接口元数据。
- models.dev 同步入口及相关文案完全移除。

交付验证包括 Go 测试、前端类型检查、相关前端测试、格式检查和本地开发环境接口验证；不进行生产构建或部署。
