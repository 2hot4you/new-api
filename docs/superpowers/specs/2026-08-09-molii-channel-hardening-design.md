# Molii AIGC 渠道可靠性加固设计

## 目标

按优先级完成五项后端加固：异步任务账务可靠性、Seedance 单渠道约束、模型映射能力与计费一致性、Grok 视频编辑分辨率的可靠计费来源、Grok 素材输入契约收敛。所有更改必须保持 SQLite、MySQL 与 PostgreSQL 兼容，并保留上游 New API 的同步能力。

## 范围与顺序

实施严格按 1→2→3→4→5 推进，每项独立测试和验收后再进入下一项。

### 1. 异步任务账务可靠性

任务的业务终态与账务终态分开保存。业务终态表示上游成功或失败；账务终态表示预扣费已经完成最终结算或退款。轮询器不得因为业务任务已经结束就永远跳过仍待处理的账务。

账务状态至少区分：无需处理、待结算、处理中、已结算、待退款、已退款、重试失败。每次账务操作使用稳定幂等键，并在数据库事务中通过条件更新领取处理权。失败后保存有限长度的脱敏错误、重试次数和下次重试时间，由现有系统任务轮询机制继续处理。并发实例只能有一个实例成功领取同一账务动作。

缺少上游任务 ID、渠道缓存临时不可用、任务超时等系统失败路径不能再仅批量写 FAILURE；这些路径必须进入统一终态与退款流程。只有账务完成后才写最终消费日志；失败日志允许先展示业务失败，但必须明确标注退款处理中。

### 2. Seedance 单渠道约束

当前产品只配置一个 Molii Volcengine Imagine API 渠道，因此不引入素材跨渠道复制、渠道亲和表或多账号路由。

系统把“仅一个启用渠道”作为当前 Seedance 素材能力的显式前置条件。素材创建与使用均验证可用渠道唯一；如果未来误配置多个启用渠道，应返回稳定、中性的配置错误，而不是随机选择渠道。现有单渠道行为保持不变，并增加回归测试保护。

### 3. 模型映射一致性

模型映射必须限制在相同能力族和价格族内。Seedance 标准版与 Fast 版、Grok legacy 与 1.5/1.5 Preview 不能通过普通模型映射跨族替换。

请求参数校验、可用操作、价格快照、预扣费、最终结算和日志展示使用同一个“有效模型”判定结果。原始模型 ID 继续用于用户日志和兼容性记录，最终上游模型用于发送请求；二者不一致时必须通过能力族校验，否则在付费前返回 400。

### 4. Grok 视频编辑分辨率

不再通过上游返回费用除以硬编码单价反推分辨率。提交时保存用户明确请求且已经校验的分辨率；完成时优先使用上游明确返回的分辨率或可信媒体元数据进行核对。

若上游协议无法提供可验证的实际分辨率，则按提交时已经快照的请求分辨率结算，并在内部账务快照中记录来源为 `requested`，不得根据费用猜测。响应或媒体明确给出不一致分辨率时，使用受支持的实际值并记录来源为 `upstream` 或 `media`。

### 5. Grok 素材输入契约

首阶段不实现通用 `/v1/files` 文件系统。Grok 图片和视频接口只接受当前能够完整验证和读取的 URL/Data URL 输入；对 `file_id` 主动返回 400 和稳定错误码，避免接受后在上游失败。

Seedance 临时素材继续使用专用 `/v1/assets` 与 `asset://` 契约，不与 OpenAI Files 语义混用。公开 OpenAPI、示例和 Docusaurus 文档只展示真实可用的输入方式。

## 错误与兼容性

- 新增错误码使用 Molii 中性命名，不出现上游品牌、渠道类型或内部 ID。
- 所有参数/映射错误必须在预扣费前返回。
- 历史任务没有账务状态时，通过兼容规则判定为既有已处理任务，不重复扣费或退款。
- 新字段由 GORM 自动迁移，并验证三种数据库。
- 账务错误与内部重试信息只对管理员日志可见；普通用户只看到业务状态和退款处理中/已完成。

## 测试

- 模型层：账务领取、并发 CAS、重试时间、历史数据兼容。
- 服务层：成功结算、失败退款、渠道缓存失败、缺少上游任务 ID、重复执行、进程中断恢复。
- 适配器：跨族映射拒绝、同族映射允许、Grok 分辨率来源、`file_id` 拒绝。
- 数据库：SQLite 单测；MySQL/PostgreSQL 由现有 CI 兼容检查覆盖。
- 集成路径：submit → persist → poll → settle/refund → log/content。

## 非目标

- 不实现多 Seedance 渠道素材复制或亲和调度。
- 不实现通用 OpenAI Files API。
- 不改变现有用户价格配置界面。
- 不修改与本任务无关的生成记录计费前端改动。
