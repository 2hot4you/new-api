# Molii 生成记录分类设计

## 目标

把面向内部实现的“任务日志”调整为面向业务的“生成记录”，并按媒体类型和模型族组织日志。用户进入页面后，可以先选择图像或视频，再选择具体模型族；列表只展示当前分类对应的数据。

## 已选方案

采用“保留现有路由，增加可扩展模型族配置，并复用现有筛选参数”的方案：

- 页面标题和侧栏名称为“生成记录”；
- 一级分类为“图像生成”和“视频生成”；
- 图像生成当前包含 `Grok Image`；
- 视频生成当前包含 `Grok Video` 和 `Seedance`；
- `/usage-logs/drawing` 继续承载图像生成，`/usage-logs/task` 继续承载视频生成；
- URL 查询参数 `source` 保存当前模型族，切换分类时回到第一页；
- `Grok Image` 继续调用 `/api/log`，并固定传递 `log_category=grok_image`；
- `Grok Video` 调用 `/api/task`，固定传递 `platform=62`；
- `Seedance` 调用 `/api/task`，固定传递 `platform=61`。

## 方案比较

1. 只改文案：改动最少，但 Grok Video 和 Seedance 仍混在同一列表，不满足分类语义。
2. 前端模型族配置加现有 API 筛选：无需新增后端契约，分类真实生效，后续增加模型族只需增加配置。采用此方案。
3. 为每个模型族新增后端日志端点：边界清晰，但会增加重复接口并扩大对上游代码的侵入，本阶段没有必要。

## 页面结构

```text
生成记录
├── 图像生成
│   └── Grok Image
└── 视频生成
    ├── Grok Video
    └── Seedance
```

一级分类保持在页面顶部，二级模型族分类位于一级分类下方。即使图像生成当前只有一个模型族，也保留 `Grok Image` 标签，以明确数据范围并为后续扩展保持一致布局。

## 兼容性与范围

- 保留现有路由路径、权限模块键和后端 API。
- 删除日志页面的 Midjourney 标签、查询分支及前端入口，但不删除后端 `/api/mj` 能力和通用渠道类型，避免无关的大范围改动。
- 旧的 `source=image`、`source=midjourney` 链接由搜索参数校验归一化到当前页面默认模型族，不产生空白页。
- 通用使用日志 `/usage-logs/common` 不受影响。

## 数据与交互

- 进入图像生成时默认选择 `Grok Image`。
- 进入视频生成时默认选择 `Grok Video`。
- 切换一级或二级分类时保留通用时间、分页大小等可复用条件，清除不适用于目标数据源的筛选字段，并将页码重置为 1。
- 列表查询键包含当前模型族，避免 React Query 在分类切换时错误复用另一模型族的数据。
- 视频筛选栏继续支持时间、任务 ID 和管理员渠道 ID 筛选。
- 图像筛选栏继续支持模型、分组、令牌、请求 ID 等现有筛选能力。

## 测试与验收

- 单元测试验证模型族与 API 参数映射：Grok Image、Grok Video、Seedance。
- 单元测试验证不再导出或使用 Midjourney 页面路由构造器。
- 类型检查、前端定向测试、格式检查和生产构建必须通过。
- 浏览器验证桌面页面标题、一级分类、二级分类、分类切换、列表数据范围和控制台健康状态。
- 在移动视口验证标签不溢出且列表仍可用。
