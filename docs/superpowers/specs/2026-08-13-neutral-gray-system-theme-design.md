# Molii 炭灰系统主色设计

## 目标

将 New API 前端当前偏蓝的品牌交互色调整为中性、克制的深炭灰，同时保留现有 Serif 字体和系统亮暗模式。此次变更只处理颜色令牌，不恢复已经关闭的主题切换功能。

## 方案

采用基础语义令牌覆盖方案，不新增可切换主题预设。

亮色模式中，`primary` 使用深炭灰并搭配近白前景色；暗色模式中，`primary` 使用较亮的中性灰并搭配深色前景色。`ring`、`sidebar-primary`、`sidebar-ring`、带有蓝色色相的 `secondary-foreground` 和 `sidebar-accent-foreground` 同步改为中性色，避免按钮已经变灰但焦点、侧栏或次级文字仍残留蓝色。

`accent` 和 `sidebar-accent` 继续由 `primary` 与背景混合生成，因此会自然得到浅灰或深灰选中态。成功、警告、错误、信息提示和数据图表保留现有颜色，以维持语义识别和数据可读性。

## 主题边界

当前 `ThemeProvider` 和 `ThemeCustomizationProvider` 已将切换方法设为空操作，公共头部和应用头部的主题入口也默认关闭。本次不修改这些行为，不挂载 `ThemeSwitch`、`ThemeQuickSwitcher` 或 `ConfigDrawer`，也不重新启用本地偏好存储。

亮暗模式仍跟随操作系统；“主色改灰”不等于强制全站只使用亮色或暗色。

## 影响文件

- `web/src/styles/theme.css`：调整基础亮色和暗色品牌交互令牌。
- 新增颜色契约测试：验证品牌令牌无蓝色色相，并验证主题切换入口仍然关闭。

如测试显示当前组件存在绕过语义令牌的硬编码品牌蓝色，只处理明确属于系统品牌交互色的用法；不扩大到模型厂商 Logo、状态色或图表颜色。

## 验证

- 先写失败的颜色契约测试，再修改令牌使其通过。
- 运行前端测试、类型检查、格式检查和本次涉及文件的 lint。
- 在本地开发环境分别模拟亮色和暗色，检查主按钮、链接、选中态、焦点环和侧栏高亮。
- 检查公共页面及登录后页面，确认主题切换按钮和配置抽屉没有恢复。
- 不执行生产构建。
